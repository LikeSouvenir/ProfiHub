# Модуль 7: Базовый React — состояние и эффекты — Практическое задание

## Проект: Трекер подготовки с загрузкой данных (PrepTracker)

### Цель

Освоить `package.json` и управление зависимостями, архитектуру проекта с именованным и дефолтным экспортом, хук `useState` (примитивы, объекты, массивы, функциональная форма обновления, иммутабельность), хук `useEffect` (массив зависимостей, эффект при монтировании, эффект на изменение, функция очистки), подъём состояния наверх (lifting state up), передачу колбэков в дочерние компоненты и контролируемые формы.

Роутинг и внешние UI-библиотеки в этом модуле **не используются**.

### Техническое задание

1. **Зависимости и `package.json`:**

   - В `README.md` разберите поля `package.json`: `name`, `version`, `type`, `scripts`, `dependencies` против `devDependencies`, значение символов `^` и `~` в версиях, назначение `package-lock.json`.

   - Поясните разницу между `npm install`, `npm ci` и `npm run build`.

2. **Структура:**

   ```
   src/
   ├── components/
   │   ├── TaskForm.jsx
   │   ├── TaskItem.jsx
   │   ├── TaskList.jsx
   │   ├── FilterBar.jsx
   │   ├── StatsPanel.jsx
   │   └── Timer.jsx
   ├── hooks/
   │   └── useLocalTasks.js
   ├── utils/
   │   └── taskUtils.js
   ├── App.jsx
   └── main.jsx
   ```

   - В `utils/taskUtils.js` — именованные экспорты вспомогательных функций (`calcProgress`, `sortTasks`, `filterTasks`).

   - Компоненты — экспорт по умолчанию.

3. **Состояние в `App.jsx` (подъём состояния):**

   - `tasks` — массив заданий `{ id, title, track, points, isDone }`.

   - `filter` — строка (`"all"` / `"active"` / `"done"`).

   - `search` — строка поиска.

   - `isLoading`, `error` — состояние загрузки и ошибки.

   - Всё состояние живёт в `App`; дочерние компоненты получают данные пропсами, а изменяют их через переданные колбэки.

4. **Загрузка данных (`useEffect` при монтировании):**

   - При первом рендере загрузите список заданий из имитированного API (функция, возвращающая `Promise` с задержкой 800 мс).

   - Пустой массив зависимостей `[]` — эффект выполняется один раз.

   - Во время загрузки показывается индикатор, при ошибке — сообщение и кнопка «Повторить».

   - Внутри эффекта используйте флаг отмены (`let cancelled = false`) и верните функцию очистки, чтобы не обновлять состояние размонтированного компонента.

5. **Иммутабельные операции над массивом (`useState`):**

   - `addTask(task)` — добавление через spread: `setTasks((prev) => [...prev, newTask])`.

   - `toggleTask(id)` — переключение через `map` с созданием нового объекта.

   - `deleteTask(id)` — удаление через `filter`.

   - `updatePoints(id, delta)` — изменение баллов через `map`, с использованием **функциональной формы** `setTasks((prev) => ...)`.

   - Прямые мутации (`tasks.push`, `task.isDone = true`) запрещены — поясните комментарием, почему React не увидит такое изменение.

6. **Контролируемая форма (`TaskForm.jsx`):**

   - Состояние формы хранится **одним объектом**: `const [form, setForm] = useState({ title: "", track: "Solidity", points: 10 })`.

   - Один универсальный обработчик `handleChange`, использующий `event.target.name` и вычисляемый ключ: `setForm((prev) => ({ ...prev, [name]: value }))`.

   - Валидация: пустой заголовок и баллы вне диапазона 1–100 не отправляются, под полем показывается текст ошибки.

   - После успешной отправки форма сбрасывается в начальное состояние.

7. **`useEffect` с зависимостями:**

   - При изменении массива `tasks` пересчитывайте и выводите в `document.title` количество невыполненных заданий: `"PrepTracker (3 активных)"`.

   - Массив зависимостей — `[tasks]`.

8. **Компонент `Timer.jsx` (эффект с очисткой):**

   - Секундомер сессии подготовки: `useState` для счётчика, `useEffect` с `setInterval`.

   - Функция очистки обязательно вызывает `clearInterval` — поясните комментарием, что произойдёт без неё.

   - Кнопки «Старт / Пауза / Сброс»; интервал запускается только когда `isRunning === true` (зависимость `[isRunning]`).

   - Время выводится в формате `MM:SS`.

9. **Производные значения без лишнего состояния:**

   - Отфильтрованный список, прогресс и статистика **вычисляются при рендере**, а не хранятся в `useState`.

   - В `StatsPanel.jsx` выведите: всего, выполнено, процент прогресса, сумма баллов, самое дорогое задание.

10. **Собственный хук `useLocalTasks.js` (по желанию, повышенная сложность):**

    - Инкапсулирует `tasks` и все операции над ними, возвращая `{ tasks, addTask, toggleTask, deleteTask, isLoading, error, reload }`.

    - `App.jsx` после этого не содержит логики работы с массивом — только композицию компонентов.

### Критерии приёмки

- Ни один обработчик не мутирует состояние напрямую — только через `setState` с новым значением.
- Все обновления, зависящие от предыдущего значения, используют функциональную форму.
- В консоли нет предупреждений о недостающих зависимостях `useEffect`.
- `setInterval` гарантированно очищается — двойной запуск таймера при повторном монтировании не возникает.
- Производные данные не продублированы в состоянии.
