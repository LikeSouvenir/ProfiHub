# Модуль 4: Продвинутые объекты и Promise — Практическое задание

## Проект: Клиент учебного API заданий (TaskApiClient)

### Цель

Освоить продвинутую работу с объектами (методы и `this`, shorthand-запись, деструктуризация объектов и массивов, деструктуризация в параметрах функции, spread- и rest-операторы, вычисляемые ключи, `Object.freeze`, методы `Object.keys/values/entries`), методы массивов объектов (`map`, `filter`, `find`, `reduce`, `sort`, `some`, `every`), а также асинхронность на `Promise`: создание, `then/catch/finally`, цепочки, `Promise.all`, `Promise.race`, `Promise.allSettled`.

### Техническое задание

Создайте файл `taskApi.js`, работающий в консоли браузера или в Node.js. Реальная сеть не используется — все «запросы» имитируются через `setTimeout` внутри `Promise`.

1. **Замороженная конфигурация:**

   - Объект `CONFIG` со свойствами `baseUrl`, `timeout`, `retries`.

   - Объект защищён от изменений через `Object.freeze`. Продемонстрируйте, что попытка перезаписи свойства не срабатывает.

2. **База данных в памяти:**

   - Массив `tasksDb` минимум из 6 объектов вида `{ id, title, track, difficulty, points, isSolved, author: { name, group } }`.

   - Поле `difficulty` — одно из `"easy"`, `"medium"`, `"hard"`; `track` — `"solidity"` / `"frontend"` / `"devops"`.

3. **Объект `taskService` с методами (shorthand-синтаксис) и `this`:**

   - Свойство `db` ссылается на `tasksDb`.

   - `getAll()` — возвращает **копию** массива через spread (не исходную ссылку).

   - `getByTrack(track)` — фильтрация через `filter`.

   - `getTotalPoints()` — сумма баллов через `reduce`.

   - `getHardest()` — задание с максимальными баллами (`reduce` или `sort` на копии массива).

   - Все методы обращаются к данным через `this.db`.

4. **Деструктуризация:**

   - Функция `describeTask({ title, points, author: { name } })` принимает объект и сразу разбирает его в параметрах, включая вложенный объект `author`. Возвращает строку-описание.

   - Продемонстрируйте деструктуризацию с переименованием и значением по умолчанию: `const { title, comment = "без комментария" } = task;`

   - Продемонстрируйте деструктуризацию массива с пропуском элемента и rest-оператором: `const [first, , ...others] = tasksDb;`

5. **Spread и rest:**

   - Функция `updateTask(task, changes)` возвращает **новый** объект: `{ ...task, ...changes }`, не мутируя исходный. Докажите неизменность оригинала выводом в консоль.

   - Функция `sumPoints(...values)` принимает произвольное число аргументов через rest и возвращает их сумму.

6. **Вычисляемые ключи:**

   - Функция `groupBy(items, key)` группирует массив объектов в объект вида `{ solidity: [...], frontend: [...] }`, где имя ключа берётся из значения поля (синтаксис `{ [computedKey]: value }`).

7. **Имитация запросов (Promise):**

   - `fetchTask(id)` — возвращает `Promise`, который через 500 мс резолвится найденным заданием либо реджектится ошибкой `new Error("Task {id} not found")`, если задания нет.

   - `fetchTaskWithDelay(id, delay)` — то же, но с настраиваемой задержкой.

8. **Цепочка `then / catch / finally`:**

   - Получите задание с существующим `id`, в `then` преобразуйте его через `describeTask`, выведите результат, в `catch` обработайте ошибку, в `finally` выведите `"Запрос завершён"`.

   - Повторите вызов с несуществующим `id` и покажите, что срабатывает `catch`, а `finally` выполняется в обоих случаях.

9. **Цепочка промисов:**

   - Постройте последовательность: получить задание → пометить решённым через `updateTask` → «сохранить» (ещё один промис с задержкой) → вывести итог. Каждое звено возвращает промис, результат передаётся дальше по цепочке.

10. **Параллельные запросы:**

    - `Promise.all` — загрузите три задания одновременно, выведите их заголовки и замерьте общее время через `Date.now()`.

    - `Promise.all` с одним отклонённым промисом — покажите, что весь набор падает в `catch`.

    - `Promise.allSettled` — тот же набор, но с выводом статуса каждого промиса отдельно.

    - `Promise.race` — два запроса с разной задержкой, побеждает быстрый.

11. **Собственный промис:**

    - Функция `checkEven(number)` возвращает `Promise`, который резолвится сообщением о чётности числа и реджектится, если аргумент не является числом (`typeof !== "number"` или `Number.isNaN`).

### Критерии приёмки

- Ни один метод не мутирует исходный массив `tasksDb` и не меняет переданные объекты.
- `Object.freeze` действительно блокирует запись (проверено выводом в консоль).
- Отклонённые промисы обработаны — необработанных `UnhandledPromiseRejection` нет.
- Разница между `Promise.all` и `Promise.allSettled` продемонстрирована на одном и том же наборе данных.
