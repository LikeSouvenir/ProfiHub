# Модуль 6: Введение в React — Практическое задание

## Проект: Витрина модулей подготовки (ModuleShowcase)

### Цель

Пройти полный путь от создания проекта до работающего интерфейса: инициализация через Vite, разбор структуры файлов (`index.html`, `main.jsx`, `App.jsx`, папка `public`), синтаксис JSX (единственный корневой элемент, фрагменты `<>...</>`, `className` вместо `class`, выражения в фигурных скобках, атрибуты), разбиение интерфейса на функциональные компоненты, передача данных через `props`, рендеринг списков через `map` с ключом `key`, условный рендеринг (тернарный оператор и `&&`), а также `props.children`.

Хуки и состояние в этом модуле **не используются** — интерфейс полностью статичен и рендерится из константного массива данных.

### Техническое задание

1. **Создание проекта:**

   ```bash
   npm create vite@latest module-showcase -- --template react
   cd module-showcase
   npm install
   npm run dev
   ```

   - В `README.md` проекта опишите назначение файлов: `index.html`, `src/main.jsx`, `src/App.jsx`, `src/index.css`, папки `public` и `src/assets`, а также файла `vite.config.js`.

2. **Структура файлов:**

   ```
   src/
   ├── components/
   │   ├── Header.jsx
   │   ├── ModuleCard.jsx
   │   ├── ModuleList.jsx
   │   ├── Badge.jsx
   │   └── Footer.jsx
   ├── data/
   │   └── modules.js
   ├── App.jsx
   ├── App.css
   └── main.jsx
   ```

3. **Данные (`src/data/modules.js`):**

   - Экспортируйте массив `modules` минимум из 6 объектов:

     `{ id, title, track, level, lessons, hours, isCompleted, tags }`

   - `track` — `"Solidity"` / `"Frontend"` / `"DevOps"`; `level` — `"базовый"` / `"средний"` / `"продвинутый"`; `tags` — массив строк.

   - Экспорт именованный: `export const modules = [...]`.

4. **`Header.jsx`:**

   - Принимает пропсы `title` и `subtitle`.

   - Для `subtitle` задано значение по умолчанию (через параметр по умолчанию при деструктуризации пропсов).

   - Возвращает шапку с заголовком и подзаголовком.

5. **`Badge.jsx`:**

   - Универсальный компонент-обёртка, использующий `props.children`.

   - Принимает `children` и `color` (`"blue"`, `"green"`, `"gray"`), подставляет соответствующий CSS-класс через шаблонный литерал: `className={`badge badge--${color}`}`.

6. **`ModuleCard.jsx`:**

   - Принимает объект модуля через пропсы (деструктуризация в параметрах).

   - Отображает: номер, заголовок, направление, уровень, количество уроков и часов.

   - **Условный рендеринг через `&&`:** если `isCompleted === true`, показывает отметку «✓ Пройден».

   - **Условный рендеринг через тернарный оператор:** цвет `Badge` зависит от уровня (`базовый` → зелёный, `средний` → синий, `продвинутый` → серый).

   - Рендерит список `tags` через `map` с уникальным `key`.

   - Вычисляет и выводит среднюю продолжительность урока: `(hours / lessons).toFixed(1)` ч.

7. **`ModuleList.jsx`:**

   - Принимает массив `modules` и заголовок секции.

   - Рендерит список карточек через `map`, передавая каждой карточке пропсы. В качестве `key` используется `module.id`, **а не индекс массива** — поясните выбор комментарием.

   - Если массив пуст, вместо списка выводит сообщение «Модули не найдены» (тернарный оператор).

8. **`App.jsx`:**

   - Собирает страницу: `Header`, три `ModuleList` (по одному на каждое направление, отфильтрованных из общего массива через `filter`), `Footer`.

   - Выводит сводку: общее число модулей, сколько пройдено, суммарное количество часов (`reduce`).

   - Возвращает **один** корневой элемент; там, где обёртка не нужна, использует фрагмент `<>...</>`.

9. **`Footer.jsx`:**

   - Принимает `year` (по умолчанию — текущий год через `new Date().getFullYear()`).

10. **Требования к JSX:**

    - Атрибут класса — только `className`.

    - Все выражения — в фигурных скобках; инлайн-стили, если применяются, передаются объектом: `style={{ color: "red" }}`.

    - Самозакрывающиеся теги обязательны: `<img />`, `<br />`.

    - Комментарии внутри JSX оформлены как `{/* ... */}`.

### Критерии приёмки

- `npm run dev` запускается без ошибок и предупреждений в консоли.
- В консоли нет предупреждения `Each child in a list should have a unique "key" prop`.
- Ни один компонент не использует `useState` или другие хуки.
- Данные приходят исключительно через пропсы — компоненты не импортируют `modules.js` напрямую (кроме `App.jsx`).
- Каждый компонент лежит в отдельном файле и имеет экспорт по умолчанию.
