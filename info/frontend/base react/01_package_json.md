# Что такое package.json и для чего он нужен

## Что это за файл
**`package.json`** — это главный конфигурационный файл любого Node.js/JavaScript-проекта (в том числе React). Он описывает: как называется проект, какие у него зависимости (используемые библиотеки), какие команды можно запускать, и другую служебную информацию.

Он автоматически создаётся при инициализации проекта (`npm init` или `npm create vite@latest`) и обновляется при каждой установке новой библиотеки.

## Структура package.json (пример React-проекта на Vite)
```json
{
  "name": "my-app",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "lint": "eslint .",
    "preview": "vite preview"
  },
  "dependencies": {
    "react": "^18.3.1",
    "react-dom": "^18.3.1"
  },
  "devDependencies": {
    "@vitejs/plugin-react": "^4.3.1",
    "vite": "^5.4.1"
  }
}
```

## Разбор ключевых полей

| Поле | Назначение |
|---|---|
| `name` | Название проекта/пакета |
| `version` | Версия проекта (формат `major.minor.patch`) |
| `private` | `true` — запрещает случайно опубликовать проект в npm-реестр |
| `type` | `"module"` — включает поддержку современного синтаксиса `import/export` |
| `scripts` | Набор именованных команд, которые можно запускать через `npm run <имя>` |
| `dependencies` | Библиотеки, необходимые для **работы** приложения (React, роутер, UI-библиотеки) |
| `devDependencies` | Библиотеки, нужные только **во время разработки** (сборщики, линтеры, тесты) — не попадают в финальную сборку для пользователей |

## scripts — команды проекта
```json
"scripts": {
    "dev": "vite",
    "build": "vite build"
}
```
Запускаются через:
```bash
npm run dev
npm run build
```
Так вместо запоминания длинных консольных команд каждый разработчик в команде использует одинаковые короткие алиасы.

## dependencies vs devDependencies на практике
```bash
# Библиотека нужна в реальной работе приложения — попадёт в dependencies
npm install axios

# Библиотека нужна только для разработки — попадёт в devDependencies
npm install --save-dev eslint
```
Значок `^` перед версией (например, `^18.3.1`) означает: можно автоматически обновляться до любой более новой **минорной** версии (18.x.x), но не до следующей мажорной (19.0.0), которая может содержать несовместимые изменения.

## package-lock.json — "снимок" точных версий
Рядом с `package.json` всегда лежит `package-lock.json` — он фиксирует **точные** версии всех установленных зависимостей (включая зависимости самих зависимостей), чтобы у всех разработчиков команды и на сервере устанавливались абсолютно одинаковые версии пакетов, а не просто "любая подходящая по `^`".

## Зачем нужен package.json на практике
1. **Воспроизводимость.** Другой разработчик (или сервер) может склонировать проект и одной командой `npm install` установить все нужные зависимости, ничего не устанавливая вручную.
2. **Документация проекта.** Сразу видно, какие технологии используются и какие команды доступны.
3. **Управление версиями.** Позволяет контролировать, какие версии библиотек допустимо использовать, избегая случайных несовместимых обновлений.

*Папка `node_modules/`, где физически хранятся все установленные библиотеки, обычно НЕ загружается в Git (добавляется в `.gitignore`) — вместо этого в репозиторий попадают только `package.json` и `package-lock.json`, а `node_modules` каждый раз воссоздаётся командой `npm install`.*
