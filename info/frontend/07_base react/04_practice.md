# Практика: useState + useEffect — число, массив и строка

## Условие
В уже созданном проекте, используя хук `useState`, сохранить значения числа, массива чисел и строки. Изменить их с помощью функций, полученных от `useState`. С помощью хука `useEffect` показать, какие значения выводятся изначально, и в этом же хуке изменить их, после чего проверить, существуют ли какие-либо изменения.

## Решение

**App.jsx**
```jsx
import { useState, useEffect, useRef } from 'react'
import './App.css'

function App() {
    // ==== 1. Три независимых состояния ====
    const [number, setNumber] = useState(10);
    const [numbersArray, setNumbersArray] = useState([1, 2, 3]);
    const [text, setText] = useState("Привет");

    // useRef хранит "предыдущие" значения между рендерами,
    // не вызывая при этом повторный рендер компонента (в отличие от useState)
    const prevValues = useRef({ number, numbersArray, text });

    // ==== 2. useEffect: выводим изначальные значения и сразу их меняем ====
    useEffect(() => {
        // Выполнится один раз, сразу после первого рендера —
        // на этом этапе на экране отображаются именно начальные значения
        console.log("=== Значения ДО изменения ===");
        console.log("number:", number);
        console.log("numbersArray:", numbersArray);
        console.log("text:", text);

        // Меняем значения прямо внутри того же useEffect
        setNumber(prev => prev + 5);                     // 10 -> 15
        setNumbersArray(prev => [...prev, 4]);            // [1,2,3] -> [1,2,3,4]
        setText(prev => prev + ", мир!");                 // "Привет" -> "Привет, мир!"

        // Пустой массив зависимостей — эффект сработает только один раз, при монтировании
    }, []);

    // ==== 3. useEffect: проверяем, были ли изменения ====
    useEffect(() => {
        const prev = prevValues.current;

        const numberChanged = prev.number !== number;
        const arrayChanged = prev.numbersArray.length !== numbersArray.length
            || prev.numbersArray.some((val, i) => val !== numbersArray[i]);
        const textChanged = prev.text !== text;

        console.log("=== Проверка изменений ===");
        console.log("number изменился:", numberChanged, "-> текущее значение:", number);
        console.log("numbersArray изменился:", arrayChanged, "-> текущее значение:", numbersArray);
        console.log("text изменился:", textChanged, "-> текущее значение:", text);

        // Обновляем "снимок" предыдущих значений для следующего сравнения
        prevValues.current = { number, numbersArray, text };

        // Срабатывает при первом рендере и затем при каждом изменении любого из трёх значений
    }, [number, numbersArray, text]);

    return (
        <div className="app">
            <h1>Проверка useState и useEffect</h1>
            <p>Число: {number}</p>
            <p>Массив: {numbersArray.join(", ")}</p>
            <p>Текст: {text}</p>
        </div>
    );
}

export default App;
```

## Что выведется в консоли
```
=== Значения ДО изменения ===
number: 10
numbersArray: [1, 2, 3]
text: Привет

=== Проверка изменений ===
number изменился: false -> текущее значение: 10
numbersArray изменился: false -> текущее значение: [1, 2, 3]
text изменился: false -> текущее значение: Привет

=== Проверка изменений ===
number изменился: true -> текущее значение: 15
numbersArray изменился: true -> текущее значение: [1, 2, 3, 4]
text изменился: true -> текущее значение: Привет, мир!
```

## Разбор решения
1. **Три `useState`** хранят три независимых типа данных: число (`number`), массив чисел (`numbersArray`) и строку (`text`) — каждое со своей парой "значение + функция-сеттер".
2. **Первый `useEffect`** с пустым массивом зависимостей `[]` выполняется единственный раз, сразу после первого рендера. В этот момент в консоль выводятся именно **начальные** значения, после чего вызываются все три функции-сеттера, которые меняют значения (используя функциональную форму `prev => ...`, чтобы гарантированно работать с актуальным предыдущим значением).
3. **`useRef`** используется для хранения "снимка" предыдущих значений между рендерами — в отличие от `useState`, изменение `.current` у `useRef` **не вызывает** повторный рендер компонента, поэтому это идеально подходит именно для хранения "истории" значений без побочных эффектов на рендеринг.
4. **Второй `useEffect`**, зависящий от `[number, numbersArray, text]`, срабатывает дважды: первый раз — сразу после монтирования (когда значения ещё исходные, поэтому `изменился: false`), и второй раз — после того, как первый `useEffect` изменил все три значения (тогда `изменился: true`). Сравнение массива идёт поэлементно, так как сравнивать массивы через `!==` напрямую нельзя — это сравнение ссылок, а не содержимого.
5. Обновление `prevValues.current` в конце эффекта гарантирует, что при дальнейших изменениях сравнение всегда идёт с действительно предыдущим, а не с самым первым состоянием.
