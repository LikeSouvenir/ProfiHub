# Архитектура системы. Export

## Компонентная архитектура React
React-приложение строится не как один большой файл разметки, а как **дерево независимых компонентов**, каждый из которых отвечает за свою небольшую часть интерфейса.

```
App
├── Header
│   ├── Logo
│   └── Navigation
├── MainContent
│   ├── Card
│   ├── Card
│   └── Card
└── Footer
```

Каждый компонент — это обычная JS-функция, которая возвращает JSX. Компоненты можно переиспользовать (как `Card` выше), передавать им данные и комбинировать в более крупные блоки.

## Однонаправленный поток данных (one-way data flow)
Ключевой архитектурный принцип React: данные передаются **только сверху вниз** — от родительского компонента к дочернему через специальный механизм **props**. Дочерний компонент не может напрямую изменить данные родителя — только сообщить об изменении через функцию, переданную ему тем же родителем.

```jsx
function App() {
    const userName = "Алина";

    return <Greeting name={userName} />; // передаём данные вниз, через props
}

function Greeting({ name }) {
    return <h1>Привет, {name}!</h1>;
}
```
Такой поток данных делает приложение предсказуемым: всегда понятно, откуda пришло то или иное значение — сверху, от какого-то конкретного родителя.

## Состояние (state) и его роль в архитектуре
Помимо props (данных "снаружи"), у компонента может быть собственное **состояние (state)** — данные, которые он хранит и изменяет сам (подробно — в следующем конспекте про хуки). Когда состояние меняется, React автоматически перерисовывает (re-render) компонент и всех его потомков, чтобы интерфейс отражал актуальные данные.

```
Состояние меняется → React перерисовывает компонент → пользователь видит обновлённый UI
```

## Разделение на "глупые" и "умные" компоненты
Частый архитектурный приём:
- **Умные (container) компоненты** — хранят состояние, содержат логику, делают запросы к серверу.
- **Глупые (presentational) компоненты** — только принимают props и отображают разметку, без собственной логики.

```jsx
// "Умный" компонент — хранит и передаёт данные
function UserPage() {
    const user = { name: "Иван", age: 25 };
    return <UserCard user={user} />;
}

// "Глупый" компонент — просто показывает то, что получил
function UserCard({ user }) {
    return (
        <div className="card">
            <h2>{user.name}</h2>
            <p>{user.age} лет</p>
        </div>
    );
}
```
Такое разделение упрощает переиспользование "глупых" компонентов в разных местах приложения с разными данными.

## Export и import — как компоненты связываются между файлами
Каждый компонент обычно живёт в своём отдельном файле и подключается к другим через `export`/`import` — тот же механизм модулей, что использовался в теме про `import` в Solidity, только применительно к JavaScript.

### Именованный экспорт (named export)
Можно экспортировать сразу несколько сущностей из одного файла:
```jsx
// utils.js
export function formatDate(date) {
    return date.toLocaleDateString();
}

export const APP_NAME = "MyApp";
```
```jsx
// App.jsx
import { formatDate, APP_NAME } from './utils.js';
```
При именованном экспорте имя при импорте **должно совпадать** с именем, под которым сущность была экспортирована (либо явно переименовывается через `as`).

### Экспорт по умолчанию (default export)
В каждом файле может быть только **один** экспорт по умолчанию — обычно так экспортируют сам компонент:
```jsx
// Card.jsx
function Card({ title, text }) {
    return (
        <div className="card">
            <h2>{title}</h2>
            <p>{text}</p>
        </div>
    );
}

export default Card;
```
```jsx
// App.jsx
import Card from './Card.jsx'; // имя при импорте можно указать любое — оно не обязано совпадать
```

### Комбинация обоих видов экспорта в одном файле
```jsx
// Card.jsx
export const CARD_MAX_WIDTH = 400; // именованный экспорт

function Card({ title, text }) {
    return (
        <div className="card" style={{ maxWidth: CARD_MAX_WIDTH }}>
            <h2>{title}</h2>
            <p>{text}</p>
        </div>
    );
}

export default Card; // экспорт по умолчанию
```
```jsx
import Card, { CARD_MAX_WIDTH } from './Card.jsx';
```

## Итоговая схема архитектуры небольшого React-проекта
```
src/
├── components/
│   ├── Card.jsx        # export default Card
│   ├── Header.jsx      # export default Header
│   └── Button.jsx      # export default Button
├── App.jsx             # import Card from './components/Card.jsx' и т.д.
└── main.jsx            # import App from './App.jsx'
```
Каждый файл отвечает за один компонент, экспортирует его через `export default`, а `App.jsx` собирает все компоненты вместе, импортируя их — точно так же, как складывается пазл из отдельных, независимо разработанных частей.
