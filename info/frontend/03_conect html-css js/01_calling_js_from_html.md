# Вызов JS-функций в HTML

Чтобы JavaScript мог реагировать на действия пользователя (клик, ввод текста, наведение мыши), нужно связать HTML-элементы с JS-кодом. Есть несколько способов это сделать.

## Способ 1: атрибут-обработчик прямо в теге (inline)
```html
<button onclick="sayHello()">Нажми меня</button>

<script>
    function sayHello() {
        alert("Привет!");
    }
</script>
```
Работает, но считается **устаревшим и нежелательным** подходом:
- JS-логика смешивается с разметкой — сложнее поддерживать.
- Нельзя повесить несколько обработчиков на одно и то же событие.
- Функция обязательно должна быть объявлена в глобальной области видимости.

## Способ 2: получение элемента и назначение обработчика через JS
Более правильный, современный подход — вся логика находится в JS-файле, HTML остаётся "чистым":

```html
<button id="myButton">Нажми меня</button>
```
```js
// Находим элемент по его id
const button = document.getElementById("myButton");

// Назначаем функцию, которая выполнится по клику
button.onclick = function () {
    alert("Привет!");
};
```

## Способ 3: addEventListener (рекомендуемый способ)
```js
const button = document.getElementById("myButton");

button.addEventListener("click", function () {
    alert("Привет через addEventListener!");
});

// Со стрелочной функцией
button.addEventListener("click", () => {
    console.log("Клик!");
});
```
Преимущества `addEventListener` перед `onclick`:
- Можно повесить **несколько** обработчиков на одно и то же событие — они не перезатирают друг друга.
- Поддерживает третий параметр с дополнительными настройками (например, срабатывание только один раз).
- Единый способ подписки на любые типы событий (`click`, `input`, `submit`, `keydown` и т.д.), а не только те, для которых есть отдельный HTML-атрибут.

```js
button.addEventListener("click", () => console.log("Первый обработчик"));
button.addEventListener("click", () => console.log("Второй обработчик"));
// При клике выполнятся ОБА обработчика по очереди
```

## Основные типы событий
| Событие | Когда срабатывает |
|---|---|
| `click` | Клик мышью по элементу |
| `input` | Изменение значения в поле ввода (сразу при каждом символе) |
| `change` | Значение поля изменилось и потеряло фокус |
| `submit` | Отправка формы |
| `mouseover` / `mouseout` | Наведение / уход курсора с элемента |
| `keydown` / `keyup` | Нажатие / отпускание клавиши клавиатуры |
| `DOMContentLoaded` | HTML-документ полностью загружен и разобран |

```js
const input = document.getElementById("username");

input.addEventListener("input", function () {
    console.log("Текущее значение поля:", input.value);
});
```

## Куда подключать script и как это влияет на работу с HTML
```html
<head>
    <!-- defer: скрипт загружается параллельно с HTML,
         но выполняется только после полной загрузки документа -->
    <script src="script.js" defer></script>
</head>
```
```html
<body>
    <h1>Страница</h1>

    <!-- Классический способ: скрипт в конце body,
         чтобы к моменту его выполнения все элементы уже существовали в DOM -->
    <script src="script.js"></script>
</body>
```
Если скрипт попытается найти элемент через `document.getElementById(...)` **до того**, как этот элемент появился в разметке — он получит `null`. Поэтому либо скрипт подключают в конце `<body>`, либо используют атрибут `defer`, либо оборачивают код в обработчик `DOMContentLoaded`:

```js
document.addEventListener("DOMContentLoaded", function () {
    // Весь код здесь гарантированно выполнится после того,
    // как HTML полностью загружен и доступен для работы
    const button = document.getElementById("myButton");
    button.addEventListener("click", () => console.log("Готово к работе!"));
});
```
