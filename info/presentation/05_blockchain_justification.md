# 5. Обоснование использования технологии блокчейн

## Что судьи хотят увидеть
Это один из самых частых провалов на защитах: команда делает рабочий продукт, но не может внятно объяснить, зачем тут вообще блокчейн, а не обычная база данных с бэкендом. Балл 3 требует полного обоснования — значит, нужно явно сравнить с альтернативой, а не просто перечислить общие свойства блокчейна.

## Универсальный чек-лист "нужен ли здесь блокчейн"
Блокчейн действительно даёт преимущество, когда в проекте есть хотя бы один из этих пунктов — используйте его как структуру слайда:

1. **Несколько взаимно недоверяющих сторон**, которым нужен общий источник истины без единого администратора данных (например: несколько компаний в цепочке поставок, которые не готовы доверять базе данных, принадлежащей одному из участников).
2. **Нужна неизменность и проверяемость истории** — важно, что запись нельзя задним числом отредактировать (сертификаты, аудиторский след, история владения активом).
3. **Программируемые правила, которые должны исполняться одинаково для всех**, без возможности одной из сторон вручную вмешаться (автоматическое распределение средств, голосование, эскроу).
4. **Прозрачность для третьих лиц** — кто угодно должен иметь возможность проверить состояние/историю, не спрашивая разрешения у владельца системы.

Если в проекте **нет** ни одного из этих пунктов — это тревожный звонок, и на слайде стоит честно объяснить, какой из них у вас есть, а не пытаться натянуть блокчейн на задачу, где хватило бы обычной БД с логированием.

## Как структурировать сам слайд
1. Одной строкой — какая из 4 причин выше у вас основная.
2. Явное сравнение "с блокчейном / без блокчейна" применительно к вашей задаче — 2–3 пункта, а не абстрактные "прозрачность, децентрализация, безопасность" общими словами.
3. Честно — какую цену вы за это платите (стоимость транзакций/комиссии, более медленная запись данных, сложность обновления логики) — признание trade-off'ов само по себе повышает доверие экспертов к докладу.

## Пример на разных доменах
- **DAO-голосование:** без блокчейна результат голосования зависел бы от честности одного сервера-организатора; на блокчейне результат проверяем любым участником напрямую по истории транзакций, а правило "1 токен = 1 голос" исполняется кодом, а не модератором.
- **Логистика/производство:** несколько независимых организаций (поставщик, производитель, экспортёр) не готовы вести общий реестр сделок в базе данных, принадлежащей одной из сторон — блокчейн даёт общую точку истины без необходимости кому-то одному доверять администрирование.
- **Реестр сертификатов:** работодателю не нужно звонить в учебное заведение, чтобы проверить диплом — публичная неизменяемая запись проверяется самостоятельно, а подделать запись задним числом нельзя.

## Частые ошибки
- Обоснование сводится к списку модных слов ("децентрализация, прозрачность, безопасность") без привязки к конкретной задаче проекта — балл 1 ("недостаточно обосновано").
- Не упомянуты недостатки/цена использования блокчейна — выглядит как маркетинг, а не инженерное решение.
- Обоснование противоречит архитектуре: например, заявлена "децентрализация", а по факту все данные хранятся в централизованной базе, а блокчейн используется только для логотипа в презентации.
