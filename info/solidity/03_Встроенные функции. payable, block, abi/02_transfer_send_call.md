# Отправка Эфира: transfer, send, call, delegatecall

В Solidity существует три основных способа перевести эфир (Ether) с баланса смарт-контракта на другой адрес. Для этого адрес получателя обязательно должен быть приведен к типу `address payable`.

## 1. transfer
Исторически самый популярный метод. 
- **Газ:** жестко ограничен (2300 газа). Этого достаточно только для перевода, но недостаточно для выполнения сложной логики на контракте получателя.
- **Ошибки:** если перевод не удался, `transfer` **автоматически вызывает revert** (откат транзакции).

```solidity
function sendViaTransfer(address payable _to) public payable {
    _to.transfer(msg.value);
}
```

## 2. send
Практически идентичен `transfer`, но с одним важным отличием в обработке ошибок.
- **Газ:** 2300 газа.
- **Ошибки:** если перевод не удался, `send` **не откатывает транзакцию**, а просто возвращает `false`. Разработчик обязан сам проверить результат.

```solidity
function sendViaSend(address payable _to) public payable {
    bool sent = _to.send(msg.value);
    require(sent, "Failed to send Ether");
}
```

## 3. call (Рекомендуемый способ)
В современных версиях Solidity (начиная с конца 2019 года) рекомендуется использовать `call` для отправки эфира. 
Из-за изменений стоимости операций в блокчейне жесткий лимит в 2300 газа стал вызывать проблемы. `call` перенаправляет весь доступный газ (или заданное количество).

- **Газ:** Передает весь оставшийся газ (можно ограничить вручную).
- **Ошибки:** Возвращает кортеж `(bool success, bytes memory data)`. Как и в `send`, вы должны сами проверить `success`.

```solidity
function sendViaCall(address payable _to) public payable {
    // Вызываем пустую функцию (нет данных) и прикрепляем value
    (bool success, ) = _to.call{value: msg.value}("");
    require(success, "Call failed");
}
```

## delegatecall
`delegatecall` — это особый вид вызова, похожий на `call`. Но есть фундаментальная разница:
При использовании `call` код выполняется в контексте (хранилище, баланс) **целевого контракта**.
При использовании `delegatecall` код целевого контракта выполняется **в контексте вызывающего контракта**. 

Это означает, что контракт А может одолжить логику (код) у контракта Б, но изменять он будет память контракта А. Это основа для создания обновляемых смарт-контрактов (Proxy паттерн).

```solidity
// Контракт А вызывает функцию контракта Б
(bool success, ) = targetAddress.delegatecall(
    abi.encodeWithSignature("setVars(uint256)", _num)
);
```
