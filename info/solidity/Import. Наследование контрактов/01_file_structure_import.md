# Файловая структура и import

По мере роста смарт-контрактного проекта хранить весь код в одном `.sol` файле становится неудобно. Solidity, как и большинство языков программирования, позволяет разносить код по разным файлам и подключать их друг к другу с помощью `import`.

## Зачем разносить контракты по файлам
- **Читаемость.** Один файл — одна сущность (контракт, интерфейс, библиотека).
- **Переиспользование.** Один и тот же контракт (например, базовый `Ownable`) можно подключать в разных проектах.
- **Совместная разработка.** Команде проще работать над разными файлами параллельно, не мешая друг другу в одном большом файле.
- **Работа с готовыми библиотеками** (например, OpenZeppelin), которые всегда поставляются в виде набора отдельных файлов.

## Типичная файловая структура проекта
```
contracts/
├── interfaces/
│   └── IToken.sol        # Интерфейсы (описание функций без реализации)
├── libraries/
│   └── MathLib.sol       # Библиотеки с переиспользуемой логикой
├── base/
│   └── Ownable.sol       # Базовые (родительские) контракты
└── Token.sol             # Основной контракт, который всё это объединяет
```

## Разбор import
Ключевое слово `import` подключает содержимое одного файла в другой, аналогично `require`/`include` в других языках.

### 1. Импорт всего файла
```solidity
import "./base/Ownable.sol";
```
Все контракты, интерфейсы и библиотеки, объявленные в `Ownable.sol`, становятся доступны в текущем файле.

### 2. Именованный импорт (только нужные сущности)
Если в файле объявлено несколько контрактов, а нужен только один — его можно импортировать точечно:
```solidity
import {Ownable} from "./base/Ownable.sol";
```
Так же можно импортировать сразу несколько сущностей через запятую:
```solidity
import {Ownable, Pausable} from "./base/Ownable.sol";
```

### 3. Импорт с переименованием (alias)
Полезно, когда имена конфликтуют или хочется более понятное имя внутри текущего файла:
```solidity
import {Ownable as BaseOwnable} from "./base/Ownable.sol";
```

### 4. Импорт всего файла в неймспейс
```solidity
import * as OwnableFile from "./base/Ownable.sol";

contract Token is OwnableFile.Ownable {
    // ...
}
```

## Относительные и абсолютные пути
- `./` — файл в той же папке.
- `../` — подняться на директорию выше.
- Путь без `./` в начале (например, `@openzeppelin/contracts/access/Ownable.sol`) — импорт из внешнего пакета, установленного через npm. Компилятор ищет такие пути в папке `node_modules`.

```solidity
// Локальный файл
import "./base/Ownable.sol";

// Внешняя библиотека из node_modules
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
```

## Пример: разбиваем проект на файлы

**base/Ownable.sol**
```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract Ownable {
    address public owner;

    constructor() {
        owner = msg.sender;
    }

    modifier onlyOwner() {
        require(msg.sender == owner, unicode"Доступ запрещен: не владелец");
        _;
    }
}
```

**Token.sol**
```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

// Подключаем контракт из соседней папки
import "./base/Ownable.sol";

// Token наследует всё, что объявлено в Ownable (см. следующий конспект)
contract Token is Ownable {
    string public name = "MyToken";
}
```

*Важно: у обоих файлов должен совпадать (или быть совместимым) диапазон версий компилятора, указанный в `pragma solidity`. Иначе компиляция завершится ошибкой.*
