# Справочник по REST API ноды

Свод самых нужных методов, которые пригодятся на чемпионате: посмотреть состояние ноды, найти информацию о транзакции, прочитать состояние смарт-контракта. Все запросы — `curl -s $NODE_URL/<путь>`, приватные методы дополнительно требуют заголовок `X-API-Key: <ключ ноды>`.

## Состояние ноды и сети

| Метод | Что возвращает |
|---|---|
| `GET /node/status` | `blockchainHeight`, `stateHeight` — высота блокчейна и высота применённого состояния; если они расходятся — нода ещё синхронизируется |
| `GET /node/version` | версия платформы, запущенной на ноде |
| `GET /node/config` | сетевые параметры: `chainId`, минимальные комиссии по типам транзакций (`minimumFee`), используемая криптография |
| `GET /blocks/height` | номер (высота) последнего блока в цепочке |
| `GET /blocks/at/{height}` | содержимое блока на конкретной высоте, включая список транзакций в нём |
| `GET /blocks/address/{address}/{from}/{to}` | все блоки, сгенерированные конкретным адресом, в диапазоне высот |
| `GET /debug/info` | служебная информация для отладки: состояние загрузки истории, статус майнинга и т.п. (приватный) |

## Транзакции

| Метод | Что делает |
|---|---|
| `POST /transactions/sign` | подписывает транзакцию ключом из keystore ноды, но не отправляет её (приватный) |
| `POST /transactions/broadcast` | отправляет уже подписанную транзакцию в сеть |
| `POST /transactions/signAndBroadcast` | подписывает и сразу отправляет — самый частый способ на этапе разработки (приватный) |
| `GET /transactions/info/{id}` | данные транзакции по её идентификатору: отправитель, тип, комиссия, высота блока, в который она попала |
| `GET /transactions/address/{address}/limit/{limit}` | последние N транзакций конкретного адреса |
| `GET /transactions/unconfirmed` | транзакции, ещё не попавшие в блок (лежат в mempool/UTX pool) |
| `POST /transactions/calculateFee` | посчитать комиссию для транзакции, не отправляя её |

## Смарт-контракты

| Метод | Что делает |
|---|---|
| `GET /contracts` | список всех контрактов сети: `contract_id`, `image`, `imageHash`, `version`, `active` |
| `GET /contracts/status/{txId}` | статус транзакции создания/вызова/обновления контракта (`SUCCESS` / `ERROR` / `FAILURE`) по её `id` |
| `GET /contracts/{contractId}` | всё текущее состояние контракта — массив пар ключ-значение |
| `POST /contracts/{contractId}` | то же состояние, но с фильтрацией: `limit`, `offset`, `matches` (regex по ключам) |
| `GET /contracts/{contractId}/{key}` | значение одного конкретного ключа состояния |
| `GET /contracts/executed-tx-for/{txId}` | результат исполнения конкретного вызова (что именно изменилось в state этим вызовом) |
| `GET /contracts/balance/details/{contractId}` | баланс системных токенов на счету контракта: `regular`, `leasedOut`, `available` |

## Типы транзакций, с которыми чаще всего работаем

| Код | Тип | Назначение |
|---|---|---|
| 103 | CreateContract | публикация нового смарт-контракта (деплой) |
| 104 | CallContract | вызов бизнес-метода уже задеплоенного контракта |
| 105 | ExecutedContract | создаётся нодой автоматически после успешного вызова — фиксирует результат |
| 106 | DisableContract | отключение (остановка) контракта |
| 107 | UpdateContract | обновление образа контракта (новая версия того же `contractId`) |

## Не забыть про params
И в 103, и в 104 транзакциях обязателен служебный параметр `{"type": "string", "key": "action", "value": "<имя метода>"}` внутри `params` — именно по нему диспетчер контракта понимает, какой `@ContractInit`/`@ContractAction`-метод вызвать. Подробнее — в файле про написание контракта.
