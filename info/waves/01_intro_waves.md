# Введение в Waves Enterprise (web3tech)

## Что это за платформа
**Waves Enterprise** (в русскоязычной экосистеме распространяется под брендом **web3tech**) — блокчейн-платформа для **приватных (permissioned) сетей**: участников сети заранее регистрирует администратор, у каждого участника есть роль и права, а не любой желающий может подключиться и писать транзакции, как в публичных сетях.

Это принципиально отличает её от публичного Waves (с языком смарт-контрактов Ride) и от Ethereum:

| | Ethereum / публичный Waves | Waves Enterprise (web3tech) |
|---|---|---|
| Кто может стать участником сети | Любой желающий | Только зарегистрированный администратором участник |
| Язык смарт-контрактов | Solidity / Ride | Java или Kotlin (через WE Contract SDK) |
| Где исполняется контракт | Внутри виртуальной машины ноды (EVM/RIDE VM) | В отдельном **Docker-контейнере**, который нода запускает и опрашивает по gRPC |
| Типичное применение | DeFi, NFT, открытые dApps | Цифровизация бизнес-процессов компании/консорциума: логистика, производство, документооборот, ЭДО |

## Из чего состоит сеть
- **Нода (node)** — основной компонент. Хранит блокчейн, принимает транзакции, предоставляет REST API и gRPC API, запускает Docker-контейнеры со смарт-контрактами.
- **Смарт-контракт** — обычное Java/Kotlin-приложение, упакованное в Docker-образ. Нода запускает этот образ как контейнер и общается с ним по gRPC, передавая вызовы и получая изменения состояния.
- **Keystore ноды** — хранилище пар "публичный/приватный ключ" участников, зарегистрированных на этой ноде. Транзакции подписываются либо самой нодой (через `/transactions/sign`, если ключ есть в keystore), либо на клиенте.
- **REST API / gRPC API** — способы взаимодействия с нодой: прочитать данные (баланс, блоки, транзакции, состояние контракта) или отправить подписанную транзакцию.

## Роли участников сети
В приватной сети у каждого аккаунта есть **сетевые permission** (не путать с ролями внутри вашего собственного смарт-контракта, о них — в файле про пользователей):

- `contract_developer` — может публиковать смарт-контракты (транзакция 103 `CreateContract`);
- `connect` — может подключаться к сети и слать обычные транзакции;
- есть и другие роли (майнинг блоков, обновление контрактов и т.д.) — их выдаёт администратор сети.

Это отдельный уровень прав "может ли адрес вообще что-то делать в сети", поверх которого уже ваш контракт может строить свою бизнес-логику ролей (админ/поставщик/клиент и т.п.).

## Жизненный цикл смарт-контракта
1. Пишете контракт на Java/Kotlin с помощью **WE Contract SDK**.
2. Собираете его в Docker-образ и публикуете в registry (Docker Hub или приватный).
3. Отправляете в сеть транзакцию **103 CreateContract** со ссылкой на образ — нода скачивает и запускает контейнер, вызывает метод, помеченный `@ContractInit`.
4. Дальше любой участник сети вызывает бизнес-методы контракта транзакцией **104 CallContract** — нода передаёт вызов в контейнер, а результат (изменения состояния) записывает в блокчейн.
5. Состояние контракта (пары ключ-значение) можно прочитать через REST API в любой момент — это и есть ваша "база данных", живущая в распределённом реестре.

Дальше по порядку: установка окружения → запуск сети нод → настройка → написание контракта → деплой → вызов методов → справочник по API.
