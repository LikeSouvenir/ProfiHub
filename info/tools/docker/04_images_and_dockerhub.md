# Сборка образов и работа с Docker Hub

## Docker Hub — что это
**Docker Hub** — крупнейший публичный реестр (registry) готовых Docker-образов, аналог GitHub, но для образов вместо кода. Именно оттуда скачиваются официальные образы вроде `node`, `nginx`, `postgres`, `python`, и туда же можно загружать собственные образы.

## Регистрация и вход
1. Зарегистрироваться на [hub.docker.com](https://hub.docker.com/).
2. Войти через терминал:
```bash
docker login
```
Потребует ввести логин и пароль (или access-токен) от Docker Hub — после успешного входа `push` и `pull` из приватных репозиториев станут доступны.

## Тегирование образов
Каждый образ идентифицируется по схеме `имя_пользователя/название_образа:тег`:
```bash
docker build -t myusername/my-app:1.0 .
```
Если тег не указан явно — по умолчанию используется `latest`, что обозначает "последнюю" версию образа (но не гарантирует автоматического обновления — это просто договорённость по именованию).

### Присвоение дополнительного тега существующему образу
```bash
docker tag my-app:1.0 myusername/my-app:1.0
docker tag my-app:1.0 myusername/my-app:latest
```
`docker tag` не создаёт новый образ физически — просто добавляет ещё одно "имя-ссылку" на уже существующий образ.

## Отправка образа на Docker Hub: docker push
```bash
docker push myusername/my-app:1.0
docker push myusername/my-app:latest
```
Обязательное условие: имя образа должно начинаться с имени пользователя (или организации) на Docker Hub — иначе Docker не поймёт, куда именно отправлять образ.

## Скачивание образа: docker pull
```bash
docker pull myusername/my-app:1.0
docker pull nginx                  # без указания пользователя — образ из официальной, проверенной библиотеки
docker pull postgres:16-alpine     # конкретная версия и вариант образа
```

## Полный цикл: от Dockerfile до Docker Hub
```bash
# 1. Собираем образ, сразу с правильным именем для Docker Hub
docker build -t myusername/my-app:1.0 .

# 2. Проверяем, что образ работает локально
docker run -d -p 3000:3000 myusername/my-app:1.0

# 3. Логинимся на Docker Hub
docker login

# 4. Отправляем образ в реестр
docker push myusername/my-app:1.0
```
После этого любой человек в мире, у кого установлен Docker, может скачать и запустить точно такое же окружение одной командой:
```bash
docker run -p 3000:3000 myusername/my-app:1.0
```

## Приватные и публичные репозитории
На Docker Hub можно создавать как **публичные** (виден всем, доступен для `docker pull` без авторизации), так и **приватные** репозитории (требуют `docker login` даже для скачивания) — бесплатный аккаунт обычно ограничен по количеству приватных репозиториев, в отличие от неограниченного числа публичных.

## Официальные образы vs образы сообщества
| Тип | Пример | Особенность |
|---|---|---|
| Официальные (Official Images) | `node`, `nginx`, `python`, `postgres` | Поддерживаются командой Docker/производителем ПО, регулярно обновляются, проходят проверки безопасности |
| Образы сообщества/пользователей | `someuser/custom-tool` | Публикуются частными разработчиками или организациями — стоит проверять содержимое Dockerfile перед использованием в продакшене |

## Выбор базового образа: практический совет
```dockerfile
FROM node:20            # "полный" образ на базе Debian — больше по размеру, больше системных утилит
FROM node:20-slim       # уменьшенная версия — меньше утилит, но заметно легче
FROM node:20-alpine     # минимальный по размеру образ на базе Alpine Linux — самый лёгкий вариант
```
Выбор зависит от задачи: `alpine` даёт самый маленький финальный образ, но иногда требует дополнительной установки системных библиотек, которые в "полной" версии уже есть по умолчанию.

## Просмотр истории образа
```bash
docker history myusername/my-app:1.0
```
Показывает все слои образа и размер, который добавляет каждая инструкция Dockerfile — полезно для поиска "тяжёлых" мест при оптимизации размера образа.
