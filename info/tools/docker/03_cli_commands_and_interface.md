# Команды Docker и интерфейс программы

## Работа с образами (images)
```bash
docker images                  # список всех локальных образов
docker pull node:20             # скачать образ из реестра (по умолчанию — Docker Hub)
docker rmi node:20               # удалить локальный образ
docker rmi $(docker images -q)   # удалить ВСЕ локальные образы (через подстановку id всех образов)
```

## Запуск контейнеров: docker run
```bash
docker run образ
```
Самая часто используемая команда, с множеством полезных флагов:

| Флаг | Значение |
|---|---|
| `-d` | Detached — запустить в фоне, не занимая терминал |
| `-p 8080:80` | Пробросить порт: `хост:контейнер` (снаружи 8080 → внутрь контейнера 80) |
| `--name мойконтейнер` | Задать понятное имя контейнеру вместо случайного |
| `-e KEY=value` | Задать переменную окружения внутри контейнера |
| `-v путь_хоста:путь_контейнера` | Примонтировать том (сохранение данных, см. ниже) |
| `-it` | Интерактивный режим + псевдо-терминал (нужен, например, для входа в контейнер через shell) |
| `--rm` | Автоматически удалить контейнер после его остановки |
| `--network имя` | Подключить контейнер к конкретной Docker-сети |

```bash
# Полный пример: запустить nginx в фоне, пробросить порт, дать имя, автоудаление после остановки
docker run -d -p 8080:80 --name my-nginx --rm nginx
```
После этого сайт из контейнера будет доступен в браузере по адресу `http://localhost:8080`.

## Просмотр и управление запущенными контейнерами
```bash
docker ps               # список ЗАПУЩЕННЫХ контейнеров
docker ps -a             # список ВСЕХ контейнеров, включая остановленные
docker stop имя_или_id   # остановить контейнер (мягко, с сигналом SIGTERM)
docker kill имя_или_id   # принудительно остановить (сразу, SIGKILL)
docker start имя_или_id  # запустить ранее остановленный контейнер заново
docker restart имя_или_id# перезапустить контейнер
docker rm имя_или_id     # удалить остановленный контейнер
docker rm -f имя_или_id  # принудительно удалить, даже если контейнер ещё запущен
```

## Просмотр логов и вход внутрь контейнера
```bash
docker logs имя_или_id           # вывести логи контейнера (то, что приложение печатает в консоль)
docker logs -f имя_или_id        # "следить" за логами в реальном времени (follow), как tail -f
```

```bash
docker exec -it имя_или_id bash    # зайти внутрь запущенного контейнера через интерактивный shell
docker exec -it имя_или_id sh      # то же самое, если внутри контейнера нет bash (частый случай в alpine-образах)
```
`exec` позволяет выполнить любую команду **внутри уже запущенного** контейнера — самый частый сценарий: отладка, проверка файлов, ручные тесты команд.

## docker build — сборка образа из Dockerfile
```bash
docker build -t мойпроект:1.0 .
```
- `-t` (`--tag`) — имя и тег будущего образа (`имя:тег`, если тег не указан — по умолчанию `latest`).
- `.` — путь к **контексту сборки** (обычно текущая папка, где лежит `Dockerfile`).

```bash
docker build -f Dockerfile.prod -t мойпроект:prod .   # указать другое имя файла Dockerfile
```

## Работа с томами (volumes) — сохранение данных
Контейнер по умолчанию "эфемерен": при удалении контейнера все данные, записанные внутри него, теряются. Тома решают эту проблему:
```bash
docker volume create my_data              # создать именованный том
docker volume ls                          # список всех томов
docker run -v my_data:/app/data образ     # подключить том к пути внутри контейнера

docker run -v /home/user/project:/app образ   # "bind mount" — примонтировать конкретную папку хоста
```
Именованные тома (`my_data`) управляются самим Docker и удобны для баз данных; bind mount (прямой путь на диске) чаще используют в разработке, чтобы изменения кода на хосте сразу отражались внутри контейнера.

## Docker-сети
```bash
docker network ls                          # список сетей
docker network create my-network           # создать собственную сеть
docker run --network my-network --name db образ  # подключить контейнер к конкретной сети
```
Контейнеры в одной пользовательской сети могут обращаться друг к другу **по имени контейнера**, как по доменному имени (например, приложение может подключаться к базе данных по адресу `db:5432`, где `db` — имя контейнера).

## Очистка системы
```bash
docker system df           # сколько места занимают образы, контейнеры, тома
docker system prune         # удалить неиспользуемые контейнеры, сети, "висячие" образы
docker system prune -a      # более агрессивная очистка — удалит и все неиспользуемые образы
```

## Интерфейс Docker Desktop
**Docker Desktop** — графическое приложение для Windows/macOS, включающее сам движок Docker и удобный визуальный интерфейс поверх командной строки.

### Основные вкладки
| Вкладка | Что показывает |
|---|---|
| **Containers** | Список всех контейнеров: запущенные/остановленные, использование CPU/памяти, кнопки Start/Stop/Delete, просмотр логов в один клик |
| **Images** | Список локальных образов, их размер, возможность запустить контейнер прямо из образа одним кликом |
| **Volumes** | Список томов, объём занятого места, содержимое |
| **Builds** | История сборок образов (`docker build`), время сборки, использование кэша слоёв |
| **Dev Environments** | Готовые окружения разработки на основе контейнеров |

### Полезные возможности интерфейса
- **Просмотр логов контейнера** без набора `docker logs` — просто клик по контейнеру → вкладка Logs.
- **Терминал внутри контейнера** — кнопка "Open in terminal" на вкладке Containers, аналог `docker exec -it ... bash`, но без набора команды.
- **Панель ресурсов** — сколько CPU/RAM/диска потребляет каждый контейнер в реальном времени.
- **Настройки ресурсов Docker** (Settings → Resources) — сколько CPU и памяти хоста разрешено использовать движку Docker в целом.

Для повседневной разработки многие используют графический интерфейс Docker Desktop для быстрого просмотра состояния контейнеров и логов, а более сложные и автоматизируемые операции (сборка в CI/CD, скриптование) выполняют через CLI-команды, разобранные выше.
