# Введение в Docker

## Проблема: "у меня на компьютере работает"
Классическая проблема разработки: приложение работает на компьютере разработчика, но падает на сервере или у коллеги — из-за разных версий языка, отсутствующих системных библиотек, различий в настройках операционной системы. **Docker** решает именно эту проблему.

## Что такое контейнеризация
**Контейнеризация** — способ упаковать приложение вместе со всем, что нужно для его работы (код, зависимости, системные библиотеки, настройки окружения), в единый, изолированный, переносимый "контейнер". Такой контейнер запускается одинаково на любой машине, где установлен Docker — на ноутбуке разработчика, на сервере компании, в облаке.

## Что такое Docker
**Docker** — самая популярная платформа для контейнеризации приложений. Позволяет:
- **Упаковать** приложение и его окружение в **образ (image)**.
- **Запустить** этот образ как изолированный, работающий **контейнер (container)**.
- **Делиться** образами через реестры (например, Docker Hub), чтобы другие могли скачать и запустить точно такое же окружение.

## Контейнеры vs виртуальные машины
Частый вопрос новичков — чем контейнер отличается от виртуальной машины (VM).

```
Виртуальная машина:                    Контейнер (Docker):

┌─────────────────────────┐            ┌─────────────────────────┐
│  Приложение А            │            │  Приложение А            │
│  Бинарники/библиотеки    │            │  Бинарники/библиотеки    │
│  Гостевая ОС (целиком!)  │            ├─────────────────────────┤
├─────────────────────────┤            │  Docker Engine            │
│  Гипервизор               │            ├─────────────────────────┤
├─────────────────────────┤            │  Хостовая ОС               │
│  Хостовая ОС               │            ├─────────────────────────┤
├─────────────────────────┤            │  Оборудование               │
│  Оборудование               │            └─────────────────────────┘
└─────────────────────────┘
```

| | Виртуальная машина | Docker-контейнер |
|---|---|---|
| Что виртуализируется | Всё "железо" целиком | Только процессы уровня ОС |
| Своя копия ОС | ✅ Да, полная гостевая ОС | ❌ Нет — использует ядро хостовой ОС |
| Размер | Гигабайты | Обычно десятки-сотни мегабайт |
| Скорость запуска | Минуты | Секунды |
| Изоляция | Максимальная (полная ОС) | Изоляция процессов и файловой системы (не оборудования) |

Контейнеры значительно легче и быстрее виртуальных машин именно потому, что не тащат за собой отдельную копию операционной системы — все контейнеры на одной машине используют одно и то же ядро хостовой ОС, но при этом остаются изолированными друг от друга по файловой системе, процессам и сети.

## Архитектура Docker
Docker работает по модели **клиент-сервер**:
```
Docker CLI (клиент)  →  команды (docker run, docker build...)
        │
        ▼
Docker Daemon (сервер, dockerd)  →  фактически создаёт и управляет контейнерами, образами, сетями
        │
        ▼
containerd / runc  →  низкоуровневый запуск изолированных процессов
```
Когда разработчик пишет `docker run ...` в терминале, команда **Docker CLI** отправляется **демону Docker (dockerd)**, который и выполняет всю фактическую работу — эта архитектура позволяет управлять Docker удалённо, не находясь физически на той же машине, где он запущен.

## Ключевые понятия
| Термин | Значение |
|---|---|
| **Image (образ)** | Готовый, неизменяемый "шаблон" — файловая система + инструкции для запуска приложения |
| **Container (контейнер)** | Запущенный, работающий экземпляр образа — можно запустить несколько контейнеров из одного образа |
| **Dockerfile** | Текстовый файл-инструкция: как именно собрать образ, шаг за шагом |
| **Registry (реестр)** | Хранилище готовых образов (например, Docker Hub), откуда их можно скачать (`pull`) или куда загрузить (`push`) |
| **Volume (том)** | Способ сохранить данные контейнера так, чтобы они не исчезали при его удалении |

## Установка Docker
- **Windows/macOS:** установить **Docker Desktop** с [docker.com](https://www.docker.com/products/docker-desktop/) — включает и сам движок Docker, и удобный графический интерфейс.
- **Linux:** устанавливается сам движок Docker Engine через пакетный менеджер дистрибутива (подробные инструкции — на официальном сайте под конкретный дистрибутив).

Проверка установки:
```bash
docker --version
docker run hello-world
```
Команда `docker run hello-world` скачивает крошечный тестовый образ и запускает его — если в терминале появляется приветственное сообщение от Docker, значит всё установлено и работает корректно.
