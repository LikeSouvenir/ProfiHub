# Введение в Git

## Что такое Git
**Git** — это система контроля версий (Version Control System, VCS). Она отслеживает изменения в файлах проекта во времени, позволяет откатиться к любой предыдущей версии, работать над кодом нескольким людям одновременно и объединять их изменения без потери данных.

Git — **распределённая** система контроля версий: у каждого разработчика на компьютере хранится **полная копия** истории проекта, а не только текущие файлы. Это отличает Git от более старых, централизованных систем (например, SVN), где полная история хранилась только на одном сервере.

## Git vs GitHub — в чём разница
Частая путаница у новичков:
- **Git** — сама программа для контроля версий, работает локально на компьютере через командную строку.
- **GitHub** (а также GitLab, Bitbucket) — облачный сервис для **хранения** Git-репозиториев в интернете, с дополнительными функциями: совместная работа, issue-трекер, code review (pull request), CI/CD.

Git можно использовать полностью локально, вообще без GitHub. GitHub, в свою очередь, без Git не работает — он построен поверх Git.

## Основные понятия
| Термин | Значение |
|---|---|
| **Repository (репозиторий)** | Папка проекта, история изменений которой отслеживается Git |
| **Commit (коммит)** | "Снимок" состояния файлов проекта в конкретный момент, с описанием изменений |
| **Branch (ветка)** | Независимая линия разработки, позволяющая работать над новой функциональностью, не затрагивая основной код |
| **Remote (удалённый репозиторий)** | Копия репозитория, размещённая на сервере (например, на GitHub) |
| **Working directory** | Текущее состояние файлов на диске, с которыми работает разработчик |
| **Staging area (индекс)** | "Промежуточная зона", куда попадают изменения перед тем, как стать коммитом |

## Три состояния файла в Git
```
Working Directory  →  Staging Area  →  Repository (после коммита)
   (изменил файл)        (git add)         (git commit)
```
1. Файл изменён в рабочей директории — Git видит, что он отличается от последнего коммита.
2. Файл добавлен в staging area (индекс) командой `git add` — "подготовлен" к попаданию в следующий коммит.
3. Файл зафиксирован в истории командой `git commit` — теперь это часть постоянной истории проекта.

## Установка Git
- **Windows:** скачать установщик с [git-scm.com](https://git-scm.com/) и установить с настройками по умолчанию.
- **macOS:** `brew install git` (через Homebrew) либо установщик с того же сайта.
- **Linux (Debian/Ubuntu):** `sudo apt install git`.

Проверка установки:
```bash
git --version
```

## Первичная настройка (config)
Перед первым коммитом Git нужно указать имя и email — они будут "подписывать" каждый созданный коммит:
```bash
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
```
Флаг `--global` означает, что настройка применяется ко **всем** репозиториям на компьютере, а не только к текущему. Без этого флага настройка применится только к репозиторию в текущей папке.

Проверить текущие настройки:
```bash
git config --list
```

## Создание первого репозитория
```bash
mkdir my-project
cd my-project
git init
```
`git init` создаёт в текущей папке скрытую служебную папку `.git/` — именно там Git хранит всю историю коммитов, ветки и настройки. Удаление папки `.git/` полностью "отвязывает" проект от Git, не трогая сами файлы.
