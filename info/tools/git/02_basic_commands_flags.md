# Базовые команды и флаги

## git status — состояние проекта
```bash
git status
```
Показывает: какие файлы изменены, какие добавлены в staging area, а какие Git вообще ещё "не видит" (untracked). Это самая часто используемая команда — с неё стоит начинать почти каждое действие.

```bash
git status -s   # или --short — компактный, однострочный вывод для каждого файла
```

## git add — добавление файлов в staging area
```bash
git add имя_файла.txt      # добавить один конкретный файл
git add папка/             # добавить все файлы внутри папки
git add .                  # добавить ВСЕ изменённые и новые файлы в текущей директории
git add -A                 # добавить все изменения по всему репозиторию (включая удалённые файлы)
git add -p                 # интерактивный режим — выбрать, какие ИМЕННО части файла добавить
```
Флаг `-p` (`--patch`) особенно полезен, когда в одном файле сделано несколько логически независимых изменений, и хочется закоммитить их отдельно, а не всё сразу.

## git commit — фиксация изменений
```bash
git commit -m "Текст сообщения коммита"
```
- `-m` — позволяет указать сообщение коммита прямо в команде, без открытия текстового редактора.

```bash
git commit -am "Сообщение"
```
- `-a` — автоматически добавляет в коммит **все уже отслеживаемые** (ранее закоммиченные хотя бы раз) изменённые файлы, минуя отдельный `git add` (но НЕ добавляет новые, ещё ни разу не закоммиченные файлы).

```bash
git commit --amend -m "Новое сообщение"
```
- `--amend` — исправляет **последний** коммит: можно изменить его сообщение или добавить в него забытые файлы (предварительно сделав `git add`). Не стоит использовать для коммитов, уже отправленных на удалённый сервер и доступных другим разработчикам.

### Хорошая практика для сообщений коммитов
```bash
git commit -m "Добавлена валидация формы регистрации"   # ✅ конкретно и понятно
git commit -m "fix"                                       # ❌ слишком расплывчато
```

## git log — история коммитов
```bash
git log
```
Показывает полную историю коммитов: автор, дата, хэш, сообщение.

```bash
git log --oneline           # компактный вывод: один коммит — одна строка
git log --oneline -5        # только последние 5 коммитов
git log --graph --oneline   # с ASCII-графом веток и слияний
git log --author="Иван"     # только коммиты конкретного автора
```

## git diff — просмотр отличий
```bash
git diff                 # отличия между рабочей директорией и staging area (что ЕЩЁ не добавлено)
git diff --staged        # отличия между staging area и последним коммитом (что добавлено, но не закоммичено)
git diff HEAD            # отличия между рабочей директорией и последним коммитом (всё вместе)
```

## git rm и git mv
```bash
git rm файл.txt          # удаляет файл и сразу помечает удаление для следующего коммита
git mv старое.txt новое.txt  # переименовывает/перемещает файл, также фиксируя изменение
```

## .gitignore — исключение файлов из отслеживания
Файл `.gitignore` в корне репозитория указывает Git, какие файлы и папки **никогда** не должны попадать под контроль версий (временные файлы, зависимости, ключи доступа):
```
node_modules/
.env
*.log
dist/
```
Файлы, попадающие под правила `.gitignore`, не будут появляться в `git status` и не могут быть случайно закоммичены через `git add .`.

## Сводная таблица частых флагов
| Флаг | Где используется | Значение |
|---|---|---|
| `-m` | `commit` | Сообщение коммита в самой команде |
| `-a` | `commit` | Автодобавление уже отслеживаемых изменённых файлов |
| `-A` | `add` | Добавить вообще все изменения в репозитории |
| `-p` | `add`, `checkout` | Интерактивный, "точечный" режим по частям файла |
| `--amend` | `commit` | Исправить последний коммит |
| `--oneline` | `log` | Компактный однострочный вывод |
| `-s` / `--short` | `status` | Короткий формат вывода |
