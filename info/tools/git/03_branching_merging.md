# Ветвление и слияние (branching & merging)

## Зачем нужны ветки
**Ветка (branch)** — независимая линия разработки. Позволяет работать над новой функциональностью или исправлением бага, не затрагивая основной, стабильный код (обычно хранящийся в ветке `main` или `master`), пока изменения не готовы и не проверены.

```
main:     A---B---C-------F---G
                    \         /
feature:             D---E---'   (слияние feature обратно в main)
```

## git branch — работа со списком веток
```bash
git branch                # список всех локальных веток (текущая отмечена звёздочкой *)
git branch имя_ветки      # создать новую ветку (но НЕ переключиться на неё)
git branch -d имя_ветки   # удалить ветку (безопасно — Git не даст удалить, если есть неслитые изменения)
git branch -D имя_ветки   # принудительное удаление ветки, даже с несохранёнными изменениями
git branch -a             # показать и локальные, и удалённые ветки
```

## git checkout / git switch — переключение между ветками
```bash
git checkout имя_ветки          # переключиться на существующую ветку (старый, универсальный способ)
git checkout -b новая_ветка     # создать новую ветку И сразу переключиться на неё

git switch имя_ветки            # переключиться (более новая, специализированная команда)
git switch -c новая_ветка       # создать и переключиться (аналог checkout -b)
```
*`git switch` появился в более новых версиях Git специально для переключения веток — `checkout` исторически выполнял сразу несколько разных задач (переключение веток, восстановление файлов), что иногда сбивало с толку.*

## git merge — слияние веток
```bash
git checkout main         # переключаемся на ветку, В КОТОРУЮ вливаем изменения
git merge feature         # вливаем ветку feature в текущую (main)
```

### Fast-forward слияние
Если в `main` со времени создания `feature` не было новых коммитов, Git просто "передвигает" указатель `main` вперёд, до последнего коммита `feature` — без создания отдельного коммита слияния:
```
До:   main:    A---B
                     \
      feature:        C---D

После: main:   A---B---C---D   (main просто "догнал" feature)
```

### Слияние с созданием merge-коммита
Если в обеих ветках были новые, независимые коммиты, Git создаёт специальный **merge-коммит**, объединяющий обе истории:
```bash
git merge feature -m "Слияние feature в main"
```

## Конфликты слияния (merge conflicts)
Конфликт возникает, когда одна и та же часть файла была изменена по-разному в обеих сливаемых ветках — Git не может понять, какую версию оставить, и просит разработчика решить это вручную.

Файл с конфликтом выглядит так:
```
<<<<<<< HEAD
Текст из текущей ветки (main)
=======
Текст из вливаемой ветки (feature)
>>>>>>> feature
```
Разработчик вручную редактирует файл, оставляя нужный вариант (или объединяя оба), удаляет служебные маркеры `<<<<<<<`, `=======`, `>>>>>>>`, а затем:
```bash
git add файл_с_конфликтом.txt
git commit   # завершает слияние специальным merge-коммитом
```

## git rebase — альтернатива merge
`rebase` "переносит" коммиты текущей ветки поверх последнего состояния другой ветки, создавая линейную историю без отдельного merge-коммита:
```bash
git checkout feature
git rebase main
```
```
До:      main:    A---B---C
                          \
         feature:          D---E

После:   main:    A---B---C
                              \
         feature (rebased):    D'---E'   (коммиты D и E "переписаны" поверх C)
```
*Важное правило: не стоит делать `rebase` для веток, которые уже отправлены на удалённый сервер и над которыми могут работать другие люди — `rebase` переписывает историю коммитов, что создаёт проблемы для всех, кто уже скачал старую версию этой истории.*

## Полезные флаги
| Команда | Флаг | Значение |
|---|---|---|
| `merge` | `--no-ff` | Всегда создавать merge-коммит, даже если возможен fast-forward |
| `merge` | `--abort` | Отменить слияние в процессе, если возник конфликт и хочется всё вернуть назад |
| `rebase` | `--abort` | Отменить rebase в процессе |
| `rebase` | `-i` | Интерактивный rebase — позволяет объединять, переставлять, редактировать коммиты перед переносом |
| `branch` | `-d` / `-D` | Безопасное / принудительное удаление ветки |
