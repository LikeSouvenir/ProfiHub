# Отчёты: покрытие тестами и расход газа

Помимо самого факта "тесты прошли/не прошли", Hardhat умеет генерировать два важных вида отчётов: **покрытие кода тестами (coverage)** и **отчёт по расходу газа (gas report)**.

## Gas Reporter — отчёт по расходу газа

### Зачем он нужен
Каждая транзакция в блокчейне стоит газ (комиссию), а газ напрямую зависит от того, насколько "тяжёлый" код у функции. Gas Reporter автоматически показывает, сколько газа тратит каждая протестированная функция контракта — это помогает находить и оптимизировать дорогие операции ещё до деплоя в реальную сеть.

### Подключение
Входит в состав `@nomicfoundation/hardhat-toolbox`, достаточно включить его в конфиге:
```js
// hardhat.config.js
require("@nomicfoundation/hardhat-toolbox");

module.exports = {
    solidity: "0.8.24",
    gasReporter: {
        enabled: true,
        currency: "USD",   // показывать примерную стоимость в валюте, а не только в газе
        // coinmarketcap: "ВАШ_API_КЛЮЧ", // опционально — для точной конвертации по текущему курсу
    },
};
```

### Запуск
```bash
REPORT_GAS=true npx hardhat test
```
После завершения тестов в терминале появится таблица:
```
·----------------------------------------|---------------------------|-------------·
|  Contract   ·  Method     ·  Min ·  Max  ·  Avg  ·  # calls ·  usd (avg)  |
|-------------|-------------|------|-------|-------|----------|-------------|
|  Storage    ·  set        · 43021 · 43021 · 43021 ·    5     ·    $0.12    |
|  Token      ·  transfer   · 51204 · 51340 · 51280 ·   12     ·    $0.15    |
·----------------------------------------|---------------------------|-------------·
```
Это позволяет заранее сравнивать разные реализации одной и той же функции по стоимости выполнения и выбирать более экономный вариант кода.

## Solidity Coverage — покрытие кода тестами

### Зачем нужно покрытие
**Покрытие тестами (code coverage)** показывает, какая доля кода контракта реально выполняется во время прогона тестов — строки, ветви условий (`if/else`), отдельные функции. Низкое покрытие — сигнал, что часть логики контракта вообще никогда не проверялась тестами, а значит там могут прятаться незамеченные ошибки.

### Установка
```bash
npm install --save-dev solidity-coverage
```
```js
// hardhat.config.js
require("solidity-coverage");
```

### Запуск
```bash
npx hardhat coverage
```
Генерирует подробный отчёт и открывает HTML-страницу (`coverage/index.html`) с построчной подсветкой:
- 🟩 зелёным — строки, которые были выполнены хотя бы одним тестом;
- 🟥 красным — строки, которые ни разу не были выполнены ни одним тестом.

Пример итогового вывода в консоли:
```
--------------------|----------|----------|----------|----------|
File                |  % Stmts | % Branch |  % Funcs |  % Lines |
--------------------|----------|----------|----------|----------|
 contracts/          |    92.31 |    83.33 |    88.89 |    92.31 |
  Storage.sol        |      100 |      100 |      100 |      100 |
  Token.sol          |    85.71 |    66.67 |       80 |    85.71 |
--------------------|----------|----------|----------|----------|
All files            |    92.31 |    83.33 |    88.89 |    92.31 |
--------------------|----------|----------|----------|----------|
```

### На что ориентироваться
- 100% покрытие **не гарантирует** отсутствие багов (код может выполняться, но результат никак не проверяется утверждениями `expect`), но низкое покрытие почти наверняка означает пропущенные сценарии.
- Особое внимание стоит уделять покрытию **ветвей (branch)** — это означает, что протестированы и `if`, и `else`, а не только "счастливый путь" выполнения кода.
- В реальных, особенно финансовых проектах, принято требовать высокое покрытие (90%+) именно ветвей и функций перед деплоем в основную сеть.

## Совмещение отчётов в рабочем процессе
```bash
npx hardhat test                    # быстрый прогон тестов при разработке
REPORT_GAS=true npx hardhat test    # прогон с оценкой стоимости газа перед оптимизацией
npx hardhat coverage                # финальная проверка полноты тестов перед релизом/аудитом
```
Такой набор отчётов — стандартная часть CI/CD-процесса серьёзных Web3-проектов: при каждом пул-реквесте автоматически прогоняются тесты, проверяется покрытие и сравнивается расход газа с предыдущей версией кода.
