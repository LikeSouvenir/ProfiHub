# HyperIndex: фреймворк индексации

## Что это такое

**HyperIndex** — полноценный индексатор, построенный поверх HyperSync. Вы описываете, что индексировать, а он сам выполняет синхронизацию, пишет в Postgres и поднимает GraphQL API.

Что даёт из коробки:

- быстрая первичная синхронизация через HyperSync (на бенчмарке Sentio по контракту Uniswap V2 Factory Envio оказался в 142 раза быстрее The Graph);
- обработчики на TypeScript (также поддерживаются JavaScript и ReScript);
- автоматическая обработка реорганизаций цепи;
- мультичейн-индексация из одного конфига;
- локальный запуск в Docker или деплой в Envio Cloud.

## Требования

- **Node.js** 22+
- **pnpm** (рекомендуется)
- **Docker Desktop** — нужен для локального запуска: индексатор поднимает Postgres и Hasura в контейнерах
- **WSL** для Windows

Docker не нужен, только если вы сразу деплоите в облако.

## Три файла проекта

Весь индексатор описывается тремя файлами:

```
my-indexer/
├── config.yaml        # какие сети, контракты и события читать
├── schema.graphql     # какие сущности (таблицы) получатся
└── src/
    └── handlers.ts    # как событие превращается в запись в БД
```

Всё остальное — сгенерированный код в папке `.envio/`, его руками не трогают.

> **Про версии.** В HyperIndex V2 обработчики лежали в `src/EventHandlers.ts` и регистрировались как `Contract.Event.handler(...)`, а сети в конфиге описывались ключом `networks`. В V3 обработчики ищутся в `src/handlers`, регистрируются через `indexer.onEvent(...)`, а ключ конфига называется `chains`. Большинство старых туториалов написаны под V2 — сверяйтесь с версией.

## Создание проекта

```bash
pnpx envio init
```

Команда задаёт несколько вопросов в интерактивном режиме. Первый выбор — способ инициализации:

```
? Choose an initialization option
  Template
> Contract Import
```

**Contract Import** — рекомендуемый путь. Индексатор генерируется прямо из контракта, двумя способами:

**1. Через блок-эксплорер** (для верифицированных контрактов). Вы указываете сеть и адрес, ABI подтягивается автоматически:

```
? Which blockchain would you like to import a contract from?
> ethereum-mainnet
  optimism
  base
  polygon

? What is the address of the contract?
[Use proxy address if ABI is for a proxy implementation]

? Which events would you like to index?
> [x] Transfer(address indexed from, address indexed to, uint256 value)
  [x] Approval(address indexed owner, address indexed spender, uint256 value)
```

**2. Через локальный ABI** — если контракт не верифицирован или вы деплоили его сами. Указывается путь к JSON-файлу ABI, затем имя контракта, сеть и адрес.

> **Важно.** Для прокси-контрактов всегда указывайте адрес **прокси**, а не адрес реализации. События эмитятся от имени прокси.

**Template** — второй вариант: готовые шаблоны `ERC20` или `Greeter` для изучения структуры.

## Запуск

Перед запуском убедитесь, что Docker запущен.

```bash
pnpm dev
```

Команда поднимает контейнеры, запускает синхронизацию и открывает панель **Hasura**, где видны проиндексированные данные и можно выполнять GraphQL-запросы.

Пароль (admin-secret) локальной Hasura — `testing`.

## Основные команды

| Команда | Что делает |
|---|---|
| `pnpx envio init` | создать новый проект |
| `pnpm dev` | запустить локально (Docker + синхронизация + Hasura) |
| `pnpm codegen` | перегенерировать типы после правки `config.yaml` или `schema.graphql` |
| `pnpm envio start -r` | перезапустить с полной переиндексацией с нуля |
| `pnpm envio stop` | остановить и удалить docker-образы окружения |
| `pnpm test` | прогнать тесты обработчиков без подключения к блокчейну |

## Горячая перезагрузка

При `pnpm dev` индексатор следит за файлами обработчиков: сохранили файл — события переобрабатываются с новой логикой без ручного перезапуска.

**Требуют полного перезапуска** (`pnpm envio start -r`):

- изменения в `config.yaml` (новые контракты, события, сети)
- изменения в `schema.graphql`
- изменения в ABI

## Как ускорить разработку

Каждый перезапуск по умолчанию начинает индексацию заново со стартового блока — на больших объёмах это долго. Три приёма:

**1. Тесты вместо синхронизации.** Встроенный фреймворк тестирования позволяет подать в обработчик фиктивное событие и проверить результат, вообще не подключаясь к блокчейну:

```bash
pnpm test
```

Это самый быстрый способ отлаживать логику обработчиков.

**2. Свежий стартовый блок.** На время разработки поставьте недавний блок:

```yaml
chains:
  - id: 1
    start_block: 19000000  # недавний блок, чтобы не ждать всю историю
```

Перед продакшеном не забудьте вернуть корректное значение.

**3. Полная переиндексация** — когда состояние испортилось или поменялась схема:

```bash
pnpm envio start -r
```

## Обработка реорганизаций (reorgs)

Блокчейн может «откатить» последние блоки, и уже записанные события окажутся невалидными. HyperIndex обрабатывает это автоматически — флаг включён по умолчанию:

```yaml
rollback_on_reorg: true  # значение по умолчанию
```

Дополнительная страховка — держать индексатор на несколько блоков позади головы цепи:

```yaml
chains:
  - id: 1
    block_lag: 5   # отставать на 5 блоков
```

Это осознанный размен: выше надёжность, но данные приходят с задержкой. По умолчанию `block_lag: 0`.

## Сравнение с The Graph

| | The Graph | Envio HyperIndex |
|---|---|---|
| Язык обработчиков | AssemblyScript (подмножество TS) | TypeScript / JavaScript / ReScript |
| Конфигурация | `subgraph.yaml` | `config.yaml` |
| Схема | `schema.graphql` | `schema.graphql` |
| Мультичейн | отдельный субграф на сеть | один конфиг на все сети |
| Скорость backfill | базовая | до 100x быстрее за счёт HyperSync |
| Self-host | `graph-node` | Docker |
| GraphQL | собственный синтаксис | стандартный GraphQL |

AssemblyScript строже TypeScript и требует отдельного изучения — это ощутимая часть порога входа в The Graph. Envio в этом смысле проще для команды, которая уже пишет фронтенд на TypeScript.
