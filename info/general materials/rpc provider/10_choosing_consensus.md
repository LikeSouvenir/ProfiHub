# Сравнение и выбор консенсуса под проект

## Сводная таблица
| Алгоритм | Модель угроз | Финализация | Пропускная способность | Децентрализация | Типичное применение |
|---|---|---|---|---|---|
| PoW | Byzantine | Вероятностная (растёт с числом подтверждений) | Низкая (~7 тр/с Bitcoin) | Высокая | Bitcoin, публичные "деньги" |
| PoS | Byzantine | Детерминированная (через эпохи) | Средняя/высокая | Средняя/высокая | Ethereum, большинство новых L1 |
| DPoS | Byzantine (среди делегатов) | Быстрая, почти детерминированная | Высокая | Низкая (ограниченный круг делегатов) | EOS, TRON |
| LPoS | Byzantine | Детерминированная | Средняя/высокая (~100 тр/с Waves-NG) | Средняя (за счёт аренды стейка) | Waves, Waves Enterprise |
| PBFT / Tendermint (BFT) | Byzantine, до трети узлов | Мгновенная, детерминированная | Высокая при небольшом n | Низкая/средняя (известный круг валидаторов) | Permissioned-сети, Cosmos |
| Raft / Paxos (CFT) | Только сбой, без злонамеренности | Мгновенная, детерминированная | Очень высокая | Низкая (доверенный круг) | Hyperledger Fabric ordering, корпоративные сети |
| PoA | Только репутационная (нет строгой мат. модели) | Быстрая | Очень высокая | Низкая | Тестовые сети, малые консорциумы |
| Avalanche (Snowman) | Byzantine, вероятностная гарантия | Суб-секундная, высокая вероятность | Очень высокая | Средняя | Avalanche и совместимые сети |

## Как выбирать консенсус для учебного/хакатонного проекта — пошаговый чек-лист
Эти вопросы прямо пригодятся на слайде "обоснование применения блокчейн-технологий" (модуль Г, файл 05) и "стек технологий" (файл 06) — отвечайте на них по порядку, ответ на каждый следующий сужает выбор:

1. **Круг участников известен заранее, или сеть должна быть открыта для анонимных участников?**
   - Известен и ограничен → рассматривайте permissioned-платформу и BFT/CFT/PoA.
   - Открыт для всех → рассматривайте публичную сеть с PoW/PoS.

2. **Насколько участники доверяют друг другу изначально?**
   - Высокий уровень доверия (одна компания, давние партнёры по контракту) → CFT (Raft) достаточно, не нужно платить за византийскую защиту.
   - Участники потенциально конкурируют или не имеют других механизмов доверия → нужен BFT даже в закрытой сети.

3. **Насколько критична скорость финализации для бизнес-сценария?**
   - Нужна мгновенная, безотзывная финализация (финансовые расчёты, юридически значимые события) → BFT/CFT/PoS с быстрой финализацией, не PoW.
   - Допустима вероятностная финализация с ожиданием подтверждений → PoW остаётся рабочим вариантом.

4. **Какая ожидаемая нагрузка (транзакций в секунду)?**
   - Высокая, много мелких операций (голосования, статусы, логи событий) → DPoS/BFT/CFT с высокой TPS.
   - Низкая, редкие крупные операции → пропускная способность не критична, можно позволить себе PoW/классический PoS ради децентрализации.

5. **Насколько важна децентрализация как продуктовая ценность именно для вашей аудитории?**
   - Ключевая ценность продукта — "никто не контролирует данные в одиночку" → жертвовать децентрализацией ради скорости нежелательно, даже если технически удобнее.
   - Децентрализация не является продающим свойством для ваших пользователей (например, внутренняя корпоративная система) → разумно выбрать более централизованный, но быстрый и дешёвый вариант (PoA/CFT).

## Как грамотно закрыть тему на слайде презентации
Плохой вариант — просто назвать используемый консенсус ("мы используем PoS"). Хороший вариант — явно провести короткую цепочку рассуждения по чек-листу выше: "у нас закрытый круг из N известных организаций → доверие среднее, участники частично конкурируют → выбрали BFT-подобный механизм вместо CFT, чтобы не полагаться на добросовестность каждого участника → это даёт мгновенную финализацию, что критично, так как в системе фиксируются юридически значимые события приёмки товара". Такое объяснение и есть содержательный ответ на критерий "обоснование применения блокчейн-технологий полностью обосновано" (балл 3, см. модуль Г).
