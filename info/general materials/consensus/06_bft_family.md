# Семейство алгоритмов на основе византийской отказоустойчивости (BFT)

## Идея
В отличие от PoW/PoS, где право предложить блок разыгрывается через конкуренцию или лотерею, BFT-алгоритмы решают задачу напрямую как классическую распределённую систему: заранее известный (или известный на момент раунда) круг участников обменивается сообщениями в несколько раундов и **голосует** за предлагаемый блок. Блок считается принятым, когда за него проголосовало достаточное большинство (обычно **более 2/3**) участников. Это даёт мгновенную, детерминированную финализацию — в отличие от вероятностной финализации PoW.

## PBFT (Practical Byzantine Fault Tolerance) — классический алгоритм
Предложен Кастро и Лисковым в 1999 году, первый практичный (не только теоретический) протокол BFT-консенсуса. Работает раундами, в каждом раунде один из узлов назначается **лидером (primary)**, остальные — репликами. Три фазы для каждого предложенного блока:

1. **Pre-prepare** — лидер рассылает всем узлам предложенный блок (пронумерованный порядковым номером в рамках раунда).
2. **Prepare** — каждый узел, получив предложение, рассылает всем остальным сообщение "я согласен с этим предложением". Узел переходит к следующей фазе, только когда сам получил **prepare**-сообщения минимум от `2f` других узлов (при общем числе узлов `n = 3f + 1`, где `f` — максимальное число византийских узлов (1/3), которое протокол выдерживает).
3. **Commit** — аналогично: каждый узел рассылает "commit", и как только набирает `2f + 1` подтверждений (включая своё) — блок считается зафиксированным окончательно, без права отмены.

Если лидер бездействует или ведёт себя недобросовестно — остальные узлы инициируют смену лидера (**view change**) по таймауту.

**Ключевая формула отказоустойчивости:** сеть из `n` узлов выдерживает до `f = (n − 1) / 3` византийских (в том числе злонамеренных) узлов — то есть система остаётся корректной, пока честных узлов **строго больше двух третей**.

## Компромисс: коммуникационная сложность
Классический PBFT требует, чтобы каждый узел обменивался сообщениями с каждым — сложность растёт квадратично от числа участников (`O(n²)`). Это делает алгоритм отличным выбором для **небольшого, заранее известного** круга участников (десятки узлов) и практически неприменимым напрямую для тысяч анонимных узлов публичной сети — отсюда прямая связь с типом сети: **BFT-алгоритмы — стандартный выбор для permissioned/консорциумных блокчейнов**, где круг валидаторов известен и ограничен.

## Tendermint / Cosmos — современный BFT для блокчейнов
Tendermint BFT — широко используемый в экосистеме Cosmos алгоритм, концептуально развивающий идеи PBFT под задачу блокчейна: раунды предложения блока и голосования (**pre-vote**, **pre-commit**) в две фазы вместо трёх, с той же гарантией — блок финализируется, когда за него проголосовало больше 2/3 валидаторов по их доле стейка (то есть Tendermint часто комбинируют с PoS: право быть предлагающим узлом в раунде зависит от доли стейка — получается **Tendermint BFT + PoS**, а не альтернатива стейкингу). Даёт мгновенную детерминированную финализацию — в отличие от вероятностной у PoW.

## Плюсы BFT-семейства
- **Мгновенная (не вероятностная) финализация** — как только блок принят, он не может быть отменён, в отличие от "подождите 6 подтверждений" в PoW.
- Высокая пропускная способность и низкая задержка при разумном числе участников.
- Математически строго доказанная устойчивость к злонамеренным узлам (при соблюдении `n ≥ 3f + 1`), а не эмпирическая, как у PoW.

## Минусы
- Плохо масштабируется на очень большое число участников из-за квадратичной коммуникационной сложности.
- Требует знать, кто участвует в консенсусе (набор валидаторов должен быть известен на момент раунда) — хуже подходит для полностью открытых анонимных сетей, чем PoW/PoS.
- Смена состава валидаторов (добавление/удаление узла) требует более сложной координации, чем в PoW, где майнер просто присоединяется или уходит без предварительной регистрации.

## Где применяется
Hyperledger Fabric может использовать BFT-подобные ordering-сервисы (хотя по умолчанию сейчас чаще применяется Raft — см. следующий файл про CFT); Cosmos SDK-based сети (Tendermint); Binance Chain; многие консорциумные банковские блокчейн-платформы.
