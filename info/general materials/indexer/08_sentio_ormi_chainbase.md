# Sentio, Ormi, Chainbase

Эти три платформы объединены в один конспект, так как решают близкую задачу похожим способом: managed SaaS-индексатор + встроенная SQL-аналитика + акцент на real-time дашборды, в отличие от "классических" self-host/subgraph-инструментов из предыдущих конспектов.

## Общая идея: индексатор как часть аналитической платформы
```
Классический подход (The Graph/Ponder/Envio):
  написать обработчики → получить GraphQL API → построить дашборд ГДЕ-ТО ЕЩЁ

Подход Sentio/Ormi/Chainbase:
  написать обработчики (или вообще без кода) → сразу получить SQL-таблицу
  И готовый дашборд/алерты в той же самой платформе
```
Ключевое отличие — эти платформы стараются закрыть весь путь "от блокчейна до дашборда" внутри одного продукта, включая визуализацию и мониторинг, а не только сырые данные для последующей обработки где-то ещё.

## Sentio

### Что умеет
- Индексация контрактов через обработчики (TypeScript) — концептуально похоже на Ponder/Envio.
- Автоматический **профилировщик вызовов** — Sentio умеет показывать, сколько газа тратит каждая функция при каждом вызове, прямо из проиндексированных данных (полезно для оптимизации, знакомой по теме Hardhat/gas reporter, но уже на реальных, ончейн-данных, а не только в тестах).
- Встроенные дашборды и алерты (например, "оповестить, если объём переводов токена X превысил Y").

### Пример обработчика (упрощённо)
```typescript
import { ERC20Processor } from "@sentio/sdk/eth/builtin";

ERC20Processor.bind({ address: "0xАдресКонтракта", network: 1 })
    .onEventTransfer((event, ctx) => {
        ctx.eventLogger.emit("Transfer", {
            distinctId: event.args.from,
            from: event.args.from,
            to: event.args.to,
            value: event.args.value,
        });
    });
```
`ctx.eventLogger.emit(...)` сразу отправляет событие во встроенную аналитическую систему Sentio — данные становятся доступны для SQL-запросов и построения графиков в интерфейсе платформы почти немедленно.

## Ormi

### Что умеет
- Специализируется на предоставлении **готовых, уже проиндексированных API** для популярных сценариев (балансы токенов, NFT-метаданные, история транзакций адреса) — то есть значительная часть работы по написанию собственных обработчиков не нужна вообще, если задача типовая.
- Подходит, когда нужен быстрый доступ к стандартным данным (например, "все NFT адреса X") без написания индексатора с нуля.
- Может использоваться и как REST/GraphQL API "из коробки", и как источник данных для дальнейшей интеграции в собственный бэкенд.

### Пример использования готового API (типовой сценарий)
```bash
curl "https://api.ormi.dev/v1/tokens/0xАдресКонтракта/holders?network=ethereum&limit=10" \
  -H "Authorization: Bearer $ORMI_API_KEY"
```
Разница с остальными инструментами раздела: здесь зачастую вообще не нужно писать собственный индексатор — достаточно вызвать готовый эндпоинт под типовую задачу.

## Chainbase

### Что умеет
- Позиционируется как связка **"блокчейн-данные + SQL + ИИ-инструменты для запросов"** — можно выполнять сложные SQL-запросы прямо к историческим ончейн-данным без построения собственного пайплайна индексации.
- Предоставляет как готовые датасеты популярных сетей, так и возможность создавать собственные, кастомные индексаторы под конкретный контракт.
- Ориентация на дата-инженеров и аналитиков, которые предпочитают писать SQL напрямую, а не TypeScript-обработчики.

### Пример SQL-запроса к готовому датасету (концептуально)
```sql
SELECT
    from_address,
    SUM(value) AS total_sent
FROM ethereum.erc20_transfers
WHERE contract_address = '0xАдресКонтракта'
  AND block_timestamp >= '2026-01-01'
GROUP BY from_address
ORDER BY total_sent DESC
LIMIT 10;
```
Такой запрос выполняется сразу к уже проиндексированным Chainbase данным всей сети — без необходимости самостоятельно поднимать что-либо для обычных, "стандартных" таблиц вроде переводов ERC20.

## Сравнительная таблица трёх платформ
| | Sentio | Ormi | Chainbase |
|---|---|---|---|
| Нужно писать обработчики? | Да (TypeScript), для кастомной логики | Часто нет — готовые API под типовые сценарии | Не обязательно — можно писать чистый SQL к готовым датасетам |
| Сильная сторона | Профилирование газа + дашборды/алерты | Готовые API под частые задачи (холдеры, метаданные) | SQL-доступ к историческим данным + ИИ-помощники для запросов |
| Кому подходит лучше всего | Командам, которым нужен мониторинг контрактов в реальном времени | Проектам, которым нужны стандартные данные быстро, без разработки | Дата-аналитикам, привыкшим работать в SQL |

## Когда выбирать SaaS-индексатор вместо self-host решения
- Нужен результат "здесь и сейчас", без построения и поддержки собственной инфраструктуры.
- В команде нет отдельного человека, отвечающего за DevOps индексатора (self-host решения вроде Ponder/Envio/Subsquid требуют собственного сервера и мониторинга).
- Важны встроенные дашборды/алерты, а не просто сырой API данных.
- Задача типовая (балансы, холдеры, история переводов) — велика вероятность, что готовое решение (особенно Ormi/Chainbase) уже покрывает её без написания кода.

**Компромисс, о котором стоит помнить:** managed SaaS-платформы удобнее и быстрее для старта, но означают зависимость от конкретного провайдера (vendor lock-in) и, как правило, дороже в долгосрочной перспективе при большом объёме запросов по сравнению с self-host инструментами вроде Ponder или Envio.
