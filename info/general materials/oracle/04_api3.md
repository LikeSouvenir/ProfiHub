# API3: first-party оракулы и dAPI

## Главное отличие — кто именно публикует данные

У большинства оракульных сетей данные проходят через посредника: независимые «ноды» опрашивают внешние API и публикуют результат в блокчейн, а протокол не знает напрямую, кто исходный источник данных.

**API3 устраняет этого посредника.** Данные публикует напрямую сам поставщик (биржа, агрегатор цен, финансовая организация) через собственный **Airnode** — программу, которую поставщик запускает сам, от своего имени, подписывая данные своим ключом. Это называется **first-party oracle**: связь «источник → блокчейн» прямая, без промежуточной сети нод, которой нужно доверять отдельно.

## dAPI — что использует разработчик

**dAPI** (decentralized API) — это агрегированный, постоянно обновляемый поток данных (по сути, price feed), составленный из нескольких first-party источников. С точки зрения контракта dAPI выглядит как любой другой push-фид: значение уже лежит в контракте, вызов — обычный `view`.

## Получение адреса прокси

Прежде чем писать код, нужен адрес **proxy-контракта** для нужной пары и сети — он выдаётся через **API3 Market** (`market.api3.org`): выбираете сеть → выбираете dAPI (например, ETH/USD) → получаете адрес прокси.

## Чтение dAPI в Solidity

```bash
npm install @api3/contracts
```

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.17;

import "@openzeppelin/contracts/access/Ownable.sol";
import "@api3/contracts/api3-server-v1/proxies/interfaces/IProxy.sol";

contract DataFeedReaderExample is Ownable {
    // Адрес прокси-контракта, полученный из API3 Market
    address public proxyAddress;

    // Смена адреса прокси — критичная для безопасности операция,
    // поэтому доступна только владельцу контракта
    function setProxyAddress(address _proxyAddress) public onlyOwner {
        proxyAddress = _proxyAddress;
    }

    function readDataFeed() external view returns (int224 value, uint256 timestamp) {
        // IProxy.read() возвращает значение и метку времени последнего обновления
        (value, timestamp) = IProxy(proxyAddress).read();

        // Как и у любого push-оракула, свежесть нужно проверять самостоятельно
        require(block.timestamp - timestamp < 1 days, "dAPI value is stale");
    }
}
```

**Обратите внимание на тип возврата** — `int224`, а не `int256`, как у Chainlink `AggregatorV3Interface`. Это осознанное отличие интерфейса API3 — при портировании кода с Chainlink на API3 нельзя просто скопировать сигнатуру.

## Формат значения

Значение dAPI приходит уже нормализованным до 18 знаков после запятой (в отличие от Chainlink, где `decimals()` варьируется между фидами) — при чтении не нужно отдельно запрашивать точность.

## OEV — Oracle Extractable Value

Особенность API3 — встроенный механизм монетизации самого момента обновления данных. Когда оракулу выгодно обновить цену (например, чтобы открыть возможность ликвидации на протоколе), это обновление можно выставить на аукцион ботам-«охотникам» (searchers) через **OEV Network**: тот, кто больше заплатит за право обновить фид первым, получает это право, а вырученные средства идут обратно в протокол, использующий dAPI — а не утекают майнерам/валидаторам, как обычно происходит с подобной ценностью (MEV).

Для учебного проекта на чемпионате это скорее концепция для понимания, чем то, что нужно интегрировать напрямую — но стоит знать, что механизм существует и в этом одно из архитектурных отличий API3 от других оракулов раздела.

## Ключевые моменты для практики

1. **`IProxy.read()`, а не `AggregatorV3Interface.latestRoundData()`.** Интерфейс своей, не Chainlink-совместимый — типичная ошибка при портировании кода между оракулами.
2. **Возврат `int224`, значение уже в 18 знаках.** Не нужен отдельный вызов за `decimals()`.
3. **Проверка свежести — так же обязательна, как у Chainlink.** Push-модель API3 не отличается от push-модели Chainlink в этом смысле: значение лежит в контракте постоянно, и just because оно там есть не значит, что оно свежее.
4. **First-party — это про доверие к источнику, а не про технический протокол доставки.** С точки зрения кода интеграция похожа на любой другой push-оракул; разница — в том, кто стоит за публикацией данных и сколько посредников между биржей и вашим контрактом.
