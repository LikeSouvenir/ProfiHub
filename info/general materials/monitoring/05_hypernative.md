# Hypernative: enterprise-платформа безопасности

## Место в общей картине

Hypernative — самый «тяжёлый» инструмент из раздела: не набор функций для одного проекта, а комплексная платформа мониторинга и автоматического реагирования, нацеленная на протоколы, биржи и институциональных управляющих активами. На чемпионате вы, скорее всего, не будете интегрировать Hypernative напрямую (доступ обычно идёт через продажи, а не самостоятельную регистрацию), но полезно понимать, какую нишу закрывает такой уровень инструмента — эта часть материала скорее для общего кругозора и для понимания того, как выглядит топ индустрии.

## Что делает платформа

- **Мониторинг 75+ сетей** в реальном времени: ончейн-данные (транзакции, поведение контрактов, governance-предложения) и офчейн-данные (веб-приложения протоколов, ценовые фиды, базы уязвимостей).
- **Более 300 типов детектируемых рисков**, объединённых в категории:
  - **Безопасность** — эксплойты, уязвимости контрактов, атаки на мосты
  - **Операционные риски** — кража приватных ключей, изменения владельца контракта, риски мультиподписи
  - **Технические** — атаки на фронтенд, инфраструктурные проблемы
  - **Финансовые** — манипуляции ценой, атаки на оракулы, депег стейблкоинов, флеш-займы
  - **Governance** — подозрительные DAO-предложения
- **Автоматический ответ**: пауза контракта, перевод средств в холодное хранилище, изменение параметров протокола — без участия человека в момент атаки.

## Ключевая возможность: Transaction Guard (mempool-уровень)

В отличие от Tenderly (симуляция по запросу разработчика) и OpenZeppelin Monitor (реакция на уже подтверждённое событие), Hypernative анализирует транзакции **на уровне мемпула** — то есть ещё до того, как транзакция попала в блок.

Принцип работы Transaction Guard:

1. Транзакция инициируется (ещё не подтверждена).
2. Платформа «распаковывает» её: какие адреса получат средства, какие approve открываются, через какие промежуточные контракты идёт вызов.
3. Транзакция сверяется со списками риска, паттернами известных атак, санкционными списками.
4. Вредоносная транзакция блокируется/карантинится **до исполнения**; легитимная — пропускается без задержки для пользователя.

Это принципиально иной уровень, чем «уведомить после события» — здесь возможна защита в реальном времени, до того как ущерб произошёл.

## API-поверхность (для ориентира)

Судя по документации, платформа предоставляет REST API по нескольким направлениям:

```
GET  /assets/reputation/addresses   — репутация/риск-скор адреса
POST /watchlists                    — управление списками наблюдения
GET  /alerts                        — получение сработавших алертов
POST /policies/transaction-guard    — настройка политик блокировки транзакций
```

Пример концептуального запроса на проверку репутации адреса (структура иллюстративная — перед реальным использованием сверяйтесь с актуальной документацией Hypernative):

```js
async function checkAddressReputation(address, apiKey) {
    const response = await fetch(
        `https://api.hypernative.io/assets/reputation/addresses/${address}`,
        { headers: { Authorization: `Bearer ${apiKey}` } }
    );

    const data = await response.json();
    return data; // риск-скор, категория угрозы, источники данных
}
```

## Firewall — политики на уровне протокола

Отдельный продукт линейки — **Hypernative Firewall**: правила допуска для конкретного протокола (allow/block листы, проверка истории нарушений, анализ параметров вызова), защищающие от flash-эксплойтов и атак в рамках одной транзакции без ухудшения опыта легитимных пользователей.

## Sequencer/RPC-интеграция для L2

Для Layer 2 сетей платформа предлагает интеграцию на уровне секвенсера — анализ и потенциальная блокировка транзакций до их включения в блок, что даёт ещё более раннюю точку вмешательства, чем классический мемпул-мониторинг на L1.

## Сравнение уровня вмешательства

| Инструмент | Момент реакции |
|---|---|
| Forta | После того, как транзакция уже в блоке — анализ постфактум |
| OpenZeppelin Monitor | После подтверждения события/блока — уведомление, опциональная реакция транзакцией |
| Tenderly Alert | После подтверждения — уведомление |
| **Hypernative Transaction Guard** | **До включения в блок** — блокировка на уровне мемпула/секвенсера |

## Ключевые моменты для практики

1. **Hypernative — не инструмент «поставить и попробовать за вечер».** Это институциональная платформа с соответствующей моделью доступа; для учебного проекта на чемпионате реалистичнее показать понимание концепции, чем реальную интеграцию.
2. **Главное отличие — момент вмешательства.** Остальные инструменты раздела реагируют постфактум (транзакция уже случилась); Transaction Guard способен предотвратить попадание вредоносной транзакции в блок вообще.
3. **На собеседовании или защите проекта** уместно продемонстрировать, что вы понимаете разницу между уровнями зрелости мониторинга: от «уведомить через минуту после события» (Monitor) до «заблокировать до исполнения» (Hypernative) — это показывает понимание архитектуры security-стека, а не просто знание конкретного SDK.
