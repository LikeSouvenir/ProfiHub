# Tenderly: симуляция, дебаггер, алерты

## Что это и зачем

Tenderly — платформа полного цикла разработки смарт-контрактов: от Node RPC и виртуальных тестовых сетей до отладки и мониторинга в продакшене. Для практики важны три возможности:

1. **Симуляция** — «проиграть» транзакцию, не отправляя её в реальную сеть, и увидеть точный результат.
2. **Дебаггер** — визуально разобрать уже случившуюся (или смоделированную) транзакцию: стек вызовов, изменения состояния, причину отката.
3. **Alert API** — уведомления при определённых условиях на контракте или кошельке.

## Регистрация и ключи

Регистрация на `tenderly.co` → создание проекта → в настройках аккаунта генерируется API-ключ (`X-Access-Key`), которым подписываются запросы к REST API.

## Симуляция через Node RPC

Самый быстрый способ — специальный RPC-метод `tenderly_simulateTransaction` на обычном Tenderly-эндпоинте ноды. Работает как любой JSON-RPC вызов:

```bash
curl https://mainnet.gateway.tenderly.co/$TENDERLY_NODE_ACCESS_KEY \
  -X POST \
  -H "Content-Type: application/json" \
  -d '{
    "id": 0,
    "jsonrpc": "2.0",
    "method": "tenderly_simulateTransaction",
    "params": [
      {
        "from": "0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045",
        "to": "0xКонтрактTaskLog",
        "gas": "0x7a1200",
        "value": "0x0",
        "data": "0xАбиЗакодированныйВызов"
      },
      "latest"
    ]
  }'
```

Ответ содержит точный результат выполнения: успех/откат, изменения балансов, использованный газ — всё это **до** реальной отправки транзакции.

## Симуляция из кода (JS)

```js
async function simulateTransaction({ from, to, data, value = "0x0" }) {
    const response = await fetch(
        `https://mainnet.gateway.tenderly.co/${process.env.TENDERLY_NODE_KEY}`,
        {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify({
                id: 0,
                jsonrpc: "2.0",
                method: "tenderly_simulateTransaction",
                params: [{ from, to, data, value, gas: "0x7a1200" }, "latest"],
            }),
        }
    );

    const { result, error } = await response.json();

    if (error) {
        // Симуляция сама показала бы revert, но сетевая ошибка (неверный
        // ключ, недоступная нода) приходит именно в это поле
        throw new Error(error.message);
    }

    return result;
}
```

**Практическое применение в интерфейсе:** перед тем как пользователь подтвердит транзакцию в кошельке, приложение прогоняет её через симуляцию и показывает точный результат («вы получите 150 USDC, газ ≈ 0.002 ETH») — вместо того чтобы пользователь узнавал результат только после реального исполнения.

## Симуляция с переопределением состояния (state override)

Можно подменить состояние блокчейна прямо в моменте симуляции — например, выдать тестовому адресу баланс токена, которого у него на самом деле нет, чтобы проверить логику без реальной подготовки данных:

```bash
curl https://mainnet.gateway.tenderly.co/$TENDERLY_NODE_KEY \
  -X POST -H "Content-Type: application/json" \
  -d '{
    "id": 0, "jsonrpc": "2.0",
    "method": "tenderly_simulateTransaction",
    "params": [
      {
        "from": "0xАдресТестовогоПользователя",
        "to": "0xКонтрактDAI",
        "gas": "0x7a1200",
        "data": "0xВызовTransfer"
      },
      "latest",
      {
        "0xКонтрактDAI": {
          "stateDiff": {
            "0xСлотХранилищаБаланса": "0x0000...0001"
          }
        }
      }
    ]
  }'
```

Это избавляет от необходимости готовить реальные тестовые данные (минтить токены, переводить средства) — состояние подменяется точечно, на уровне конкретного слота хранилища.

## REST Simulation API — с сохранением в дашборд

RPC-симуляции не сохраняются в интерфейсе Tenderly. Если нужно сохранить результат для дальнейшего разбора командой (например, приложить ссылку в баг-репорт):

```js
async function simulateAndSave({ from, to, data, value = "0" }) {
    const { TENDERLY_ACCOUNT_SLUG, TENDERLY_PROJECT_SLUG, TENDERLY_ACCESS_KEY } = process.env;

    const response = await fetch(
        `https://api.tenderly.co/api/v1/account/${TENDERLY_ACCOUNT_SLUG}/project/${TENDERLY_PROJECT_SLUG}/simulate`,
        {
            method: "POST",
            headers: {
                "Content-Type": "application/json",
                "X-Access-Key": TENDERLY_ACCESS_KEY,
            },
            body: JSON.stringify({
                network_id: "1",
                from,
                to,
                input: data,
                value,
                save: true,           // сохранить даже при успехе
                save_if_fails: true,  // сохранить обязательно при неудаче
            }),
        }
    );

    const simulation = await response.json();

    // simulation.id даёт прямую ссылку на дебаггер
    console.log(`Разбор: https://dashboard.tenderly.co/.../simulator/${simulation.id}`);

    return simulation;
}
```

> **Важно про стоимость.** Каждый вызов `/simulate`, даже с одинаковым телом запроса, расходует Tenderly Units (400 TU за вызов) — результаты не кешируются на стороне Tenderly, кеширование при повторных одинаковых симуляциях нужно делать на своей стороне.

## Виртуальные тестовые сети (Virtual TestNets)

Отдельная возможность — поднять изолированную копию реальной сети (со всем её текущим состоянием на выбранном блоке) и работать в ней как в собственном тестовом окружении: деплоить контракты, слать транзакции, отматывать время и блок вперёд. В отличие от одноразовой симуляции, тестовая сеть сохраняет состояние между вызовами — подходит для сценариев из нескольких шагов подряд (approve → swap → withdraw).

Ранее для этого использовался Fork (устарел с 31 марта 2025 года) — в новых проектах используется **Virtual TestNets**.

```bash
curl -X POST \
  https://api.tenderly.co/api/v1/account/{username}/project/{project}/fork \
  # ...
```

Для нового кода правильнее создавать Virtual TestNet через дашборд или его API-аналог, а не через устаревший `/fork`-эндпоинт.

## Alert API — уведомления

Алерт настраивается по условиям на события/функции/параметры транзакции. В дашборде это делается визуально; программно — через API с более чем 12 типами триггеров (событие эмитирован, функция вызвана, баланс кошелька изменился, газ превысил порог и т.д.).

Каналы доставки: email, Slack, Discord, Telegram, вебхук, Web3 Actions.

## Web3 Actions — код-реакция на событие

Аналог функции-обработчика, которая запускается автоматически при срабатывании условия — например, при получении алерта можно тут же вызвать внешний API или (в связке с Relayer другого инструмента) отправить транзакцию-реакцию.

## Ключевые моменты для практики

1. **Симуляция — не то же самое, что `eth_call`.** `eth_call` показывает только успешный возвращаемый результат view-функции. Симуляция Tenderly прогоняет полноценную транзакцию (включая `nonpayable`/`payable` функции) и показывает изменения состояния, события, использованный газ — то, что `eth_call` в принципе не умеет.
2. **RPC-метод для разработки, REST API — для сохранения и командной работы.** Быстрая проверка «сработает — не сработает» — через `tenderly_simulateTransaction`; если результат нужно разобрать вместе с командой или приложить к отчёту об ошибке — через `/simulate` с `save: true`.
3. **State override экономит время на подготовке тестовых данных.** Не нужно реально минтить токены или готовить баланс — состояние подменяется на лету, только для конкретной симуляции.
4. **Каждый вызов API стоит ресурсов.** На хакатоне лимит бесплатного тарифа расходуется быстро при частом дублировании одинаковых запросов — кешируйте результат на своей стороне, если симуляция не меняется между вызовами.
